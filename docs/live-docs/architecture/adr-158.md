# ADR-158: No fallback to a higher tier without a recorded FallbackJustification carrying one of four enumerated reasons

**Date:** 2026-05-09T21:30:18.874Z  
**Status:** accepted  
**Decided by:** collaborative  
**Affected entities:** extensions/vscode/src/architect-v2/execution/policy.ts, extensions/vscode/src/architect-v2/execution/inventory.ts  

## Context

v1 silently substituted shell or VS Code tools when an MCP tool was unavailable or threw. The user could not tell from the card that a fallback had occurred, and the agent could not distinguish 'DreamGraph chose VS Code' from 'DreamGraph could not reach MCP'. The user directive at Slice 4 kickoff requires this to be visible and naturally rare.

**Constraints:**
- The user directive 'fall back to VS Code only when it proves necessary' must be auditable post-hoc.
- Cards must show WHY a fallback occurred without consulting external state.
- Tier promotion (DreamGraph → fallback) must never happen silently; tier demotion (fallback → DreamGraph) is impossible by construction.
- The four reasons cover every legitimate fallback case; any new case requires a superseding ADR.

## Decision

When `selectExecutor` chooses a tier higher (numerically) than `preferredTierForIntent(intent)`, it MUST attach a `FallbackJustification` with one of four reasons: `'mcp_tool_unavailable'`, `'mcp_tool_failed'`, `'intent_not_covered_by_dreamgraph'`, or `'editor_native_required'`. The orchestrator records this on the `PassRecord`. When the preferred tier IS already a fallback tier (T4/T5), `'editor_native_required'` is attached so cards render the right pill. There is no code path that returns a fallback plan without a justification.

### Alternatives Considered

- **Walk all 5 tiers regardless and pick the best** — Rejected: Even with strict ordering the algorithm would still consult fallback descriptors, opening the door for accidental fallback when the DreamGraph entry is technically present-but-flaky. Stopping the walk at the first DreamGraph hit makes 'available' the binding signal.
- **Allow fallback when MCP latency exceeds a threshold** — Rejected: Latency-based fallback is policy that belongs to the orchestrator, not to the selector. The selector's job is to identify the canonical executor; runtime decisions about whether to retry, time out, or switch live one layer up.
- **Treat `editor_native_required` as not-a-fallback (don't justify it)** — Rejected: Cards still need to render a 'editor-native' pill so the user knows why a Tier-4 tool was chosen for what looks like a routine intent. Justification records that fact.

## Consequences

- The 90–100% DreamGraph-coverage target becomes measurable: count `FallbackJustification` occurrences per session, watch for clusters of `'mcp_tool_unavailable'` indicating a daemon issue, or `'intent_not_covered_by_dreamgraph'` indicating a catalog gap to close.
- Cards render fallback pills with one of four reasons — user can see at a glance why VS Code/shell was used.
- Telemetry can flag any session where DreamGraph fallback rate exceeds a threshold for review.
- Slice 6 capability matrix uses the catalog directly; this ADR ensures runtime behavior matches what the matrix promises.

**Risks accepted:**
- A noisy MCP daemon (frequent transient failures) will produce many `mcp_tool_unavailable` justifications. Intentional — the noise is the signal that the daemon needs attention.
- Producers may declare a too-narrow intent that only a Tier-4 tool covers, then claim 'editor_native_required' even when a DreamGraph tool would have served. Mitigation: catalog reviewers + Slice 6 parity matrix surface coverage gaps.

## Guard Rails

> ⚠️ Do not return an `ExecutionPlan` with `tier > preferredTier` and `fallbackJustification === undefined`. The selector enforces this.

> ⚠️ Do not invent a fifth fallback reason without a superseding ADR.

> ⚠️ Do not let the orchestrator strip `fallbackJustification` from the `PassRecord` — it's part of the audit trail.

> ⚠️ Do not surface a `FallbackJustification` to the model in a way that lets it dismiss the fallback as 'fine'; cards should treat it as a noteworthy event.
