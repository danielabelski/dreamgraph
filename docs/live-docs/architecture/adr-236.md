# ADR-236: Incremental reconciliation uses a journaled cross-store commit boundary

**Date:** 2026-08-14T11:02:47.551Z  
**Status:** accepted  
**Decided by:** collaborative  
**Affected entities:** feature_incremental_additive_scan_plan, data_scan_state_v1, graph_enrichment  

## Context

Incremental scan must update multiple instance JSON stores without exposing a partially committed graph or allowing concurrent reconciliation to interleave.

**Constraints:**
- Existing stores remain independent JSON files
- atomicWriteFile guarantees one-file replacement only
- Full scan remains recovery authority
- Instance-aware locking must serialize reconciliation

## Decision

Use one instance-scoped reconciliation lease plus a durable write-ahead journal containing previous and next store bodies. Check the expected scan revision before commit, publish writes under the lease, remove the journal only after all writes succeed, and roll back from the journal on failure or daemon recovery.

### Alternatives Considered

- **Immutable revision directories with an active pointer** — Rejected: Requires all readers and data-path consumers to become revision-aware in one breaking migration.
- **Best-effort independent atomic writes** — Rejected: Can expose mixed old/new graph state and cannot safely recover after interruption.

## Consequences

- Concurrent incremental scans serialize
- Revision conflicts fail safely
- Interrupted commits are recoverable to the previous complete state
- Existing store readers remain compatible

**Risks accepted:**
- Rollback cost scales with the bounded stores in one transaction
- Readers not using the reconciliation barrier can observe a short commit window until migrated

## Guard Rails

> ⚠️ Do NOT commit incremental multi-store mutations outside the reconciliation lease and journal.

> ⚠️ Do NOT delete the journal before every store write succeeds.

> ⚠️ Do NOT bypass expected-revision checks for incremental commits.

> ⚠️ Full scan recovery must remain operational if incremental metadata is missing or incompatible.
