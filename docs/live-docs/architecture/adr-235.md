# ADR-235: Standalone Architect route boundary evidence is anchored on handleArchitectRoute

**Date:** 2026-06-11T02:53:55.688Z  
**Status:** accepted  
**Decided by:** collaborative  
**Affected entities:** standalone_architect_daemon_routes, src/architect/routes.ts, api_surface, ADR-208, ADR-215, ADR-216  

## Context

The current API surface extraction missed the standalone Architect route symbol even though source inspection shows handleArchitectRoute is the exported daemon-owned HTTP boundary for /architect and /api/architect/v1. Future reasoning needs a durable anchor that this pass added curated API-surface evidence without claiming a new runtime implementation.

**Constraints:**
- Implementation status must remain evidence-bound per ADR-234; this pass records evidence and API-surface curation, not a new executable feature.
- Standalone Architect remains daemon-authoritative under ADR-206 and the versioned /api/architect contract under ADR-208.
- Prompt-bearing chat transport, runtime identity, and plan/chat scope guard rails from ADR-215, ADR-216, and ADR-219 remain binding.
- Curated API surface updates are allowed to correct stale extraction but must not supersede source-code verification.

## Decision

Treat src/architect/routes.ts::handleArchitectRoute as the current curated API-surface anchor for the standalone Architect daemon route boundary. Use source inspection and future API-surface refreshes to maintain the index; do not infer implementation changes from this evidence-only curation pass.

### Alternatives Considered

- **Leave the stale/missing API-surface entry unrecorded** — Rejected: Future graph/API-surface queries could continue to miss the canonical route function and force repeated rediscovery.
- **Claim this pass implemented a new standalone Architect route feature** — Rejected: No source behavior was changed; ADR-234 requires implementation claims to be grounded in executable source changes and verification.

## Consequences

- Future API-surface queries can find handleArchitectRoute even before a full extractor refresh.
- Graph reasoning can link standalone_architect_daemon_routes to its source route function and binding ADR constraints.
- The pass remains correctly classified as evidence/curation plus verification, not implementation.

**Risks accepted:**
- The hand-curated API-surface entry may drift if handleArchitectRoute is renamed or refactored without refreshing the index.
- Additional route helper functions in src/architect/routes.ts may still be underrepresented until extraction is refreshed.

## Guard Rails

> ⚠️ Do not treat curated API-surface entries as a substitute for source verification before behavior changes.

> ⚠️ Do not claim route implementation status from graph/API-surface curation alone.

> ⚠️ Refresh or recurate the API surface if handleArchitectRoute is renamed, split, or moved.

> ⚠️ Keep standalone Architect route behavior constrained by ADR-208, ADR-215, ADR-216, and ADR-219 unless superseded.
