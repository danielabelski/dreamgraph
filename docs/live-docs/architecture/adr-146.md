# ADR-146: Architect v2 Slice 1 demolition baseline: full v1 surface inventory + per-slice handoff contracts

**Date:** 2026-05-09T19:58:41.935Z  
**Status:** accepted  
**Decided by:** collaborative  
**Affected entities:** plans/ARCHITECT_V2_SLICE1_INVENTORY.md, extensions/vscode/src/, ADR-140, ADR-141, ADR-142, ADR-143, ADR-144, ADR-145  

## Context

The Architect v2 rewrite needs a verified, exhaustive baseline of what exists in v1 today \u2014 every file, every smell, every Copilot-parity gap, every MCP-bypass point, every migration risk \u2014 so future slices can be grounded in evidence rather than memory or assumption, and so the v10.0.0 cutover commit has a precise deletion manifest. Without this baseline, the rewrite would inherit v1's patch-stacking by accident.

**Constraints:**
- Rewrite must not assume v1 internals — must be grounded in a verified read-only inventory.
- User explicitly required no assumptions and no shortcuts; demolition map must be exhaustive.
- Cutover commit at v10.0.0 must have a precise file-deletion list to be auditable.
- All future slices must be able to cite specific inventory sections as their input — no implicit dependencies.
- Inventory must agree across Markdown (plans/) and ADR (graph) representations per ADR-142.

## Decision

Slice 1 of the Architect v2 rewrite produces a complete demolition baseline for the v1 Architect surface (~17000 LOC across ~60 files in extensions/vscode/src/), captured in plans/ARCHITECT_V2_SLICE1_INVENTORY.md and mirrored as ADR-140 through ADR-146. The inventory enumerates: (a) per-surface current-state map covering chat path, cards, autonomy, providers, tool execution, context engine, memory/continuity, prompts, and webview; (b) ranked patch-stacking smells (top severity: three parallel envelope extractors causing the user-visible 'summaries render as JSON and autonomy stops working' bug); (c) Copilot-parity gaps to close in v2; (d) MCP-bypass points violating the graph-first principle; (e) migration risks for future slices to plan around; (f) precise deletion manifest for the v10.0.0 cutover commit; (g) target shape skeleton for architect-v2/ directory. Slice 1 closes when the architect-v2/ skeleton exists with empty placeholders and a README referencing this ADR. All subsequent slices (2 through 7) consume specific sections of this inventory as their declared input.

### Alternatives Considered

- **Skip the inventory and start writing v2 code** — Rejected: Without a demolition map, v2 risks accidentally reproducing v1 smells (parallel envelope extractors, dual budget systems, hardcoded magic numbers); the user explicitly rejected assumptions and shortcuts.
- **Build v2 incrementally without a final cutover deletion list** — Rejected: Leaves a half-migrated state where v1 and v2 share file paths; ADR-140 already rejected this. The deletion list is the contract that makes the cutover commit auditable.
- **Inventory only the smelliest files (chat-panel.ts, autonomy-*)** — Rejected: Partial inventory would miss the cross-cutting smells (three trimming layers, two budget systems, three envelope extractors) that only become visible when the full surface is mapped.

## Consequences

- Every v2 slice has a verifiable input contract pointing at specific inventory sections; no slice begins on assumption.
- The v10.0.0 cutover commit has a precise deletion manifest — ~35 v1 source files identified for removal.
- Three top-severity user-visible smells (parallel envelope extractors, dual autonomy analysis, three trimming layers) are explicitly tagged for elimination in slices 3, 4, and 5.
- MCP-bypass points are catalogued so slice 4 can systematically reroute them through the dispatcher.
- Cross-cutting risks (persisted-schema drift, tool collisions, envelope drift) are pre-identified so slices can build mitigations from the start, not discover them late.

**Risks accepted:**
- Inventory may miss subtle implicit contracts that only surface during slice implementation — reconciliation ADRs will be required as discoveries happen.
- v1 may receive bugfix changes during the rewrite that drift the deletion manifest; mitigated by guard rail requiring explicit list maintenance.
- Inventory document is large; future readers must navigate by section rather than reading top-to-bottom.

## Guard Rails

> ⚠️ Do not start a v2 slice without citing the specific inventory section(s) it consumes.

> ⚠️ Do not modify plans/ARCHITECT_V2_SLICE1_INVENTORY.md after Slice 1 close without recording a reconciliation ADR.

> ⚠️ Do not let the deletion manifest in inventory §6 drift from reality — if a v1 file is added after Slice 1, decide explicitly whether it joins the deletion list.

> ⚠️ Do not declare any v2 slice complete until both its Markdown plan and its mirroring ADR(s) exist per ADR-142.

> ⚠️ Do not skip Slice 1's architect-v2/ skeleton scaffolding step — it is the closure condition for Slice 1.
