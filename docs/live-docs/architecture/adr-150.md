# ADR-150: Cloud provider defaults locked: OpenAI gpt-5.5 (Responses) + gpt-5.4 (Chat) equal-class; Anthropic claude-4.7 xhigh

**Date:** 2026-05-09T20:48:43.768Z  
**Status:** accepted  
**Decided by:** collaborative  
**Affected entities:** extensions/vscode/src/architect-v2/providers/openai.ts, extensions/vscode/src/architect-v2/providers/anthropic.ts, ADR-145, ADR-147  

## Context

ADR-145 locked the local-provider flagship defaults (LM Studio gpt-oss-120b high-context, Ollama qwen2.5-coder:32b) but did not name the cloud-provider flagship defaults. Slice 2 needs these locked too, both so first-run users land on a quality default and so verification can assert them mechanically.

**Constraints:**
- ADR-145 locked local-provider defaults but left cloud defaults implicit; this ADR closes that gap.
- First-run users must land on a deliberate, high-quality default without any settings interaction.
- Defaults must be mechanically discoverable so verification (Slice 2 §6 criteria 3-4) can assert them.

## Decision

Architect v2 cloud provider defaults are explicitly locked. OpenAI flagship default = `gpt-5.5` via Responses API. OpenAI equal-class second = `gpt-5.4` via Chat Completions (previous API). Anthropic flagship default = `claude-4.7` with `defaultEffort: 'xhigh'`. These values are encoded as `defaultModelId` on each provider profile and as `defaultEffort` inside the model's `ReasoningSupport`. Settings may override per-user; the registry-level default may not be silently changed.

### Alternatives Considered

- **Defer cloud defaults to user settings only** — Rejected: Reproduces the v1 ambiguity inventory §5 calls out; new users with no settings would land on whatever the registry lists first, which is implicit and brittle.
- **Always default to the cheapest model in each provider** — Rejected: The Architect rewrite explicitly targets quality and tool-call reliability; defaulting to a weaker model would systematically degrade out-of-box behavior to save cost the user did not opt into.
- **Default to the most recent model id at registry-build time** — Rejected: Couples defaults to release timing rather than to a deliberate quality choice; would silently change defaults on every cloud release that adds a newer id.

## Consequences

- First-run experience for cloud providers matches the rewrite's quality intent without any user configuration.
- Slice 2 verification can assert defaults by inspection of the registry.
- Future cloud-default changes require an explicit superseding ADR, not a quiet model-list edit.

**Risks accepted:**
- Cloud providers occasionally rename or sunset model ids; the lock will need a superseding ADR if `gpt-5.5` or `claude-4.7` is renamed/retired.
- Defaulting to high-effort reasoning (Anthropic xhigh) increases per-request cost; this is intentional for quality but should be visible to cost-conscious users via settings.

## Guard Rails

> ⚠️ Do not change `defaultModelId` for `openai` away from `gpt-5.5` without a superseding ADR.

> ⚠️ Do not change `defaultModelId` for `anthropic` away from `claude-4.7` without a superseding ADR.

> ⚠️ Do not change Anthropic's `defaultEffort` away from `xhigh` without a superseding ADR.

> ⚠️ Do not silently demote a default to a cheaper model id; cost-driven defaults require explicit user opt-in.
