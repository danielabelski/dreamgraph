# ADR-120: export_living_docs covers datastores, auxiliary entities, and tensions

**Date:** 2026-05-03T12:47:13.509Z  
**Status:** accepted  
**Decided by:** collaborative  
**Affected entities:** feature_export_living_docs, feature_living_docs_exporter, data_model_datastores, data_model_auxiliary_entities, data_model_tension_log, workflow_export_living_docs  

## Context

After Slice 4B (tension resolution lifecycle) and Slice 5B (extended scanning of datastores + auxiliary entities: MCP tools, test suites, configuration files, automation scripts), the living-docs exporter only emitted features, data_model, workflows, architecture, ui_registry, cognitive_status, and api_reference. New canonical knowledge stores (`datastores.json`, `auxiliary_entities.json`, `tension_log.json` with resolution candidates) had no published surface, breaking the documentation-sync rule and hiding live cognitive state from consumers.

**Constraints:**
- Must be backward compatible — existing section names and `all` semantics keep working.
- Must not require LLM calls — generators are pure JSON-to-Markdown transformations.
- Must gracefully degrade when source JSON is missing or empty (no error, just zero buffers).
- Must respect existing format adapters (docusaurus / nextra / mkdocs / plain) via `frontmatter` helper.
- Must keep `cognitive_status` opt-in via `include_cognitive` even under `all`.

## Decision

Extend the `LivingDocsSection` union with `datastores`, `auxiliary`, and `tensions`, add corresponding loaders (`loadDatastores`, `loadAuxiliaryEntitiesFile`) and pure generators (`genDatastores`, `genAuxiliary`, `genTensions`), and wire them into VALID_SECTIONS, the `all` expansion, the dispatch ladder, and the index `sectionLabels`. The auxiliary section groups by `kind` (mcp_tool, test_suite, configuration, automation_script). The tensions section surfaces open-by-type counts, top-25 by urgency, and the Slice 4B resolution candidates with strategy + validation window.

### Alternatives Considered

- **Emit datastores/auxiliary/tensions only via new dedicated tools** — Rejected: Would fragment the docs surface, force consumers to discover and stitch together separate exporters, and duplicate format adapter logic.
- **Roll datastores into the existing `data_model` section** — Rejected: Datastores have a distinct schema (kind/url_hint/tables[] introspected by `scan_database`) that is operationally different from logical data_model entries, and bundling them would obscure the introspection vs. modeling distinction.
- **Skip tensions in living docs because state is volatile** — Rejected: Resolution candidates from Slice 4B are an architecturally significant surface and consumers need to see the heuristic strategies in published docs.

## Consequences

- Living docs reflects the full v8.2 entity surface — Slice 4B + 5B work is discoverable.
- Documentation-sync rule (.github/copilot-instructions.md) is honored for the new stores.
- Auxiliary entity coverage gives future tooling a stable per-kind URL pattern.

**Risks accepted:**
- Tension snapshots are volatile — exported tensions page can drift between exports; consumers must understand it is a snapshot, not a log.
- Auxiliary kind taxonomy is fixed in `KIND_ORDER`; introducing a fifth kind requires touching the generator.
- Datastore pages depend on `scan_database` having populated `tables[]`; exports will be sparse until the daemon has introspected each datastore.

## Guard Rails

> ⚠️ Do NOT remove or rename the `datastores`, `auxiliary`, or `tensions` section identifiers — they are part of the public tool contract.

> ⚠️ Do NOT make any of the new generators depend on LLM calls or network IO; they must remain pure JSON-to-Markdown.

> ⚠️ Do NOT include `cognitive_status` in the `all` expansion implicitly; the `include_cognitive` opt-in must continue to gate it.

> ⚠️ Do NOT silently swallow load errors without returning an empty buffer set — failure to read should not crash the whole export.

> ⚠️ Any new entity store added in the future MUST also extend the exporter (LivingDocsSection union, loader, generator, sectionLabels, VALID_SECTIONS, all-expansion, dispatch) before being considered shipped.
