# ADR-096: Cold-start mode dual exit (entity-count OR cycle/time window)

**Date:** 2026-05-03T10:27:16.663Z  
**Status:** accepted  
**Decided by:** human  
**Affected entities:** src/cognitive/normalizer.ts, src/cognitive/engine.ts, src/cognitive/strategies, validated_edges.json, candidate_edges.json  

## Context

Normalizer's strict promotion thresholds (confidence ≥ 0.62, evidence ≥ 0.4, evidence_count ≥ 2, entity-existence required) are unreachable on a cold-start graph because the evidence signal is circular — entities must already be in the graph to count. validated_edges.json stays empty and the dream→normalize→promote loop never produces actionable output on fresh instances.

**Constraints:**
- Must terminate (no infinite cold-start)
- Must not be defeated by very small or domain-narrow repos that legitimately contain few entities
- Must not prematurely tighten on slow-growing graphs
- Tuning floors must be empirically observable, not guessed

## Decision

Add a cold-start mode in the normalizer with relaxed thresholds (drop entity-existence requirement, count domain/keyword overlap as evidence, lower confidence floor to ~0.50). Mode exits via a DUAL condition — whichever fires first: (A) entity-count threshold (≥ 50 entities AND ≥ 10 validated edges), OR (B) bootstrap window elapsed (20 dream cycles OR 24h of daemon uptime). Telemetry records exit_reason: "size" | "window" | "manual".

### Alternatives Considered

- **Entity-count threshold only** — Rejected: Tiny / domain-narrow repos may never reach the count and stay in cold-start forever.
- **Time/cycle window only** — Rejected: Slow-growing graphs would prematurely tighten before enough evidence accumulated.
- **Lower thresholds permanently** — Rejected: Sacrifices long-term graph quality for short-term bootstrap convenience.

## Consequences

- Fresh instances begin producing validated edges within the first ~20 cycles
- Telemetry on exit_reason allows empirical tuning of the 50/10/20/24h floors
- Existing mature instances behave identically once they exit the bootstrap window

**Risks accepted:**
- Relaxed thresholds may admit lower-quality edges during bootstrap window
- Dual-condition logic adds branching to a hot path in the normalizer
- exit_reason telemetry must actually be reviewed for the tuning loop to close

## Guard Rails

> ⚠️ Do NOT remove the dual-condition exit — entity-count and window must both remain

> ⚠️ Do NOT raise the relaxed floor above 0.50 confidence without revisiting this ADR

> ⚠️ Do NOT extend the bootstrap window beyond 24h without telemetry justification

> ⚠️ exit_reason field MUST remain populated on every cold-start exit event
