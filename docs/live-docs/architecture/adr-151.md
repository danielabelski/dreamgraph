# ADR-151: Architect v2 autonomy is a pure deriveNextAction() function returning a DecisionResult discriminated union

**Date:** 2026-05-09T21:18:40.319Z  
**Status:** accepted  
**Decided by:** collaborative  
**Affected entities:** extensions/vscode/src/architect-v2/autonomy/decision.ts, extensions/vscode/src/architect-v2/autonomy/task.ts, extensions/vscode/src/architect-v2/autonomy/signals.ts, extensions/vscode/src/architect-v2/autonomy/capability.ts, plans/ARCHITECT_V2_SLICE3_AUTONOMY.md  

## Context

v1 autonomy spreads decision logic across `autonomy.ts`, `autonomy-loop.ts`, `autonomy-structured.ts`, and `autonomy-contract.ts`. Mode-specific behavior is encoded as switch branches inside `chooseActionForMode` and `shouldContinueAfterPass`, mixed with empty-pass heuristics and pass-envelope parsing. Inventory \u00a71.5 lists this as the LARGEST single tangle in v1. v2 needs a single pure decision function so the rest of the rewrite has one stable seam to depend on.

**Constraints:**
- Same inputs MUST always produce the same `DecisionResult` (replayability for debugging and auditing).
- The decision module must be provider-agnostic — no import from `architect-v2/providers/`.
- Slice 4 (MCP-first execution) needs a stable `CapabilityInventory` interface to plug into.
- Slices 5–7 each consume a distinct piece of this contract; the shape must accommodate them without breaking changes.

## Decision

Architect v2 autonomy is a pure function `deriveNextAction(taskState, inventory, candidates, now) -> DecisionResult`. `DecisionResult` is a discriminated union: `{ kind: 'continue', need: ContinuationNeed } | { kind: 'pause_for_user', reason, ranked, note } | { kind: 'stop', condition: StopCondition }`. The function reads `TaskState` (mode, profile, passes, blockers, budgets, status), the `CapabilityInventory`, and a list of `ActionCandidate`s; it never calls a provider, never mutates state, never performs I/O. The orchestrator owns state transitions and pass execution; the autonomy module owns only the decision.

### Alternatives Considered

- **Port v1 `shouldContinueAfterPass` rule cascade verbatim** — Rejected: v1's cascade entangles mode-specific branching with budget checks, scope checks, empty-pass heuristics, and uncertainty enums in a single function. The user directive at Slice 3 kickoff was 'carry only the concept and the settings' — not the implementation. Porting verbatim would re-import the architecture this rewrite exists to remove.
- **Make `deriveNextAction` an event-emitting class with internal state** — Rejected: Hidden state breaks reproducibility — we can't replay a decision from a `TaskState` snapshot if the engine carries its own state across calls. Pure function with explicit inputs is auditable and trivially testable.
- **Defer the decision contract to Slice 5 (cards) where the UI integration lives** — Rejected: Every later slice (MCP execution, cards, capability matrix, verification harness) consumes some part of this contract. Defining it now lets all four be designed against the same seam.

## Consequences

- Decisions are testable as plain function calls with literal `TaskState` fixtures.
- Bug reports can include a `TaskState` snapshot and a `nowEpochMs` and be reproduced exactly.
- Slices 4–7 each plug into a stable seam without negotiating new contracts.
- Removing v1 `autonomy*.ts` at the v10 cutover is a single deletion + import flip, not a coordinated multi-file refactor.

**Risks accepted:**
- The discriminated union may need to widen as Slices 4–7 surface new requirements; widening is OK, narrowing is a breaking change.
- If `CapabilityInventory` from Slice 4 turns out to need async lookup, the function signature widens to async — mitigated by keeping the Slice 3 stub synchronous and asserting that capabilities are pre-resolved before `deriveNextAction` is called.
- Pure-function discipline requires callers to pass `nowEpochMs` rather than calling `Date.now()` inside; missing this in callers re-introduces hidden non-determinism.

## Guard Rails

> ⚠️ Do not add I/O (network, disk, terminal, vscode API) inside the autonomy module.

> ⚠️ Do not mutate any input to `deriveNextAction`; the function is pure.

> ⚠️ Do not move state transitions into the autonomy module — the orchestrator owns them.

> ⚠️ Do not import from `architect-v2/providers/` inside `architect-v2/autonomy/`.

> ⚠️ Do not bypass `createContinuationNeed()` to construct a `ContinuationNeed` literal — the constructor enforces ADR-154.
