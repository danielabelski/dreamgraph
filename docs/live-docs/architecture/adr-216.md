# ADR-216: Standalone Architect runtime identity is a daemon-owned session object

**Date:** 2026-05-28T17:52:10.620Z  
**Status:** accepted  
**Decided by:** collaborative  
**Affected entities:** src/architect/routes.ts, tests/standalone-architect-routes.test.ts, standalone_architect_active_session_runtime, standalone-architect  

## Context

Standalone Architect previously assembled adapter, provider, model, autonomy, top-bar labels, chat route context, trace metadata, and provenance from separate UI and daemon fields. That allowed selector state, actual runtime state, and assistant prompt context to diverge, making model identity unreliable as governance metadata during native API, Codex CLI, Copilot CLI, deterministic fallback, and audit flows.

**Constraints:**
- Model identity is governance metadata and must be available to UI, prompt context, traces, and provenance from one authoritative object.
- Browser selectors may mutate runtime state only through daemon-governed POST endpoints and persisted engine.env keys; they must not become an independent source of truth.
- CLI adapters remain intermediate execution routes, not native API providers, so adapter identity and provider identity must both be represented.
- Runtime identity must not expose secrets or raw prompt content.
- ADR-206/ADR-210 daemon-served standalone Architect boundaries and ADR-201 native CLI adapter boundaries remain binding.

## Decision

Represent the active standalone Architect execution identity as a daemon-owned session runtime object containing adapter, provider, model, autonomy_mode, pass_state, execution_route, and session_id. Return this runtime in status/config/chat/future-review payloads, render the top bar from it, mutate it through the config endpoint, inject it into chat system context, and attach it to route, trace, and provenance metadata.

### Alternatives Considered

- **Keep selector state, route metadata, and chat prompt metadata independently assembled.** — Rejected: This preserves the mismatch that caused the UI to show one model while the assistant lacked reliable runtime identity.
- **Treat the provider/model selector as the source of truth in browser localStorage.** — Rejected: Browser-local state is not authoritative governance metadata and can drift from engine.env and daemon execution.
- **Collapse CLI adapters into provider values.** — Rejected: Codex CLI and Copilot CLI are intermediate adapter routes, not native API providers; collapsing them would violate adapter/provider boundaries.

## Consequences

- Top-bar runtime labels, selector persistence, chat context, tool traces, and provenance refer to the same session runtime object.
- The assistant can answer its current adapter/provider/model/session identity from injected runtime context instead of claiming uncertainty.
- Runtime changes remain auditable through daemon payloads and engine.env persistence.
- Future adapter work can attach richer execution details without changing the core runtime identity contract.

**Risks accepted:**
- The initial standalone runtime object is process-local and may need durable session lifecycle refinements later.
- CLI adapter execution is still metadata-only in this standalone path until full CLI orchestration is ported.
- Additional UI surfaces may need migration from legacy architect_llm aliases to runtime over time.

## Guard Rails

> ⚠️ Do not make browser localStorage, selector DOM state, or chat request fields the authoritative runtime identity.

> ⚠️ Do not let top-bar labels, prompt context, trace metadata, and provenance derive adapter/provider/model from different sources.

> ⚠️ Do not collapse Codex CLI or Copilot CLI into native API provider values; keep adapter and provider separate.

> ⚠️ Do not log secrets, raw prompts, or raw tool payloads as part of runtime identity.

> ⚠️ Do not remove runtime identity from chat system context or provenance without an equivalent daemon-owned replacement.
