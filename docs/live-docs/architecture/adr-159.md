# ADR-159: Slice 5 — Cards persist DG-heavy: every card field durable in DreamGraph

**Date:** 2026-05-09T21:53:02.408Z  
**Status:** accepted  
**Decided by:** collaborative  
**Affected entities:** extensions/vscode/src/architect-v2/cards/persistence.ts, extensions/vscode/src/architect-v2/cards/types.ts  

## Context

v1 cards lived only in webview state; lost on reload, invisible to dream cycles, narrative, and other graph-aware tools. Foundation ADR-143 mandates split persistence so cards become first-class graph artifacts.

**Constraints:**
- No I/O in Slice 5 (pure split mapper)
- Strict isolation from v1 (ADR-140)
- Ephemeral state limited to UI flags (collapsed ids, scroll, focused id)
- Cards immutable; updates produce successor cards via parentCardId

## Decision

DG-heavy split persistence: DurableCardRecord wraps the entire Card (destined for MCP entity storage in Slice 7); EphemeralCardState restricted to {collapsedCardIds, scrollPosition, focusedCardId}; splitForPersistence() is a pure mapper. Alternatives rejected: webview-heavy (cards lost on reload, invisible to graph-aware tools); dual-write (doubles writes for no recovery benefit); lazy flush on completion only (blockers and partials lost on crash).

## Consequences

- Cards become queryable graph artifacts citable by dream cycles, narrative, and ADRs
- Reloads never lose execution history
- Webview becomes a thin disposable renderer

**Risks accepted:**
- Per-card MCP write cost if synchronous — mitigate with batching in Slice 7
- Schema bumps require coordinated migration across persisted records

## Guard Rails

> ⚠️ splitForPersistence is pure — no Date.now, no Math.random, no I/O

> ⚠️ Ephemeral state stays UI flags only; no business data leaks in

> ⚠️ DurableCardRecord wraps the full Card — no field omission, no partial persistence

> ⚠️ Cards immutable; updates produce successor cards via parentCardId

> ⚠️ Slice 5 ships shape only; persistence I/O wiring belongs to Slice 7
