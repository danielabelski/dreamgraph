# ADR-149: Hybrid model-list source: TS const tables for cloud providers, runtime discovery for local providers

**Date:** 2026-05-09T20:48:43.746Z  
**Status:** accepted  
**Decided by:** collaborative  
**Affected entities:** extensions/vscode/src/architect-v2/providers/openai.ts, extensions/vscode/src/architect-v2/providers/anthropic.ts, extensions/vscode/src/architect-v2/providers/lmstudio.ts, extensions/vscode/src/architect-v2/providers/ollama.ts, extensions/vscode/src/architect-v2/providers/profile.ts, ADR-147  

## Context

Inventory \u00a75 flags 'Provider model-list rot' as a v1 risk: hardcoded `ANTHROPIC_MODELS` and `OPENAI_MODELS` arrays go stale, while local providers (LM Studio, Ollama) host different models on different user machines and cannot be enumerated statically at all. A single mechanism cannot serve both.

**Constraints:**
- Cloud provider model lists are stable and benefit from compile-time validation.
- Local provider model rosters are user-specific and change frequently as users pull/delete models.
- Default model resolution must work at extension activation without requiring network calls (per Slice 2 verification criterion 3-6).
- Inventory §5 risk 'Provider model-list rot' must be addressed for cloud providers without imposing release friction on local-provider users.

## Decision

Architect v2 uses a hybrid model-list source. Cloud providers (`openai`, `anthropic`) ship their model lists as TypeScript const tables in `providers/openai.ts` and `providers/anthropic.ts` \u2014 type-checked, versioned with code, requires a release to add a model. Local providers (`lmstudio`, `ollama`) declare `modelSource: 'discovery'` and obtain their model lists at runtime via the provider's own discovery endpoint (LM Studio `/v1/models`, Ollama `/api/tags`). Slice 2 ships the discovery seam only; the Slice 2 `listModels()` for local providers returns a single-entry list containing the locked default (ADR-145) so the registry resolves consistently without network. Slice 3+ replaces the seam with real fetch + caching.

### Alternatives Considered

- **TS const tables for all four providers** — Rejected: Local providers (LM Studio, Ollama) host different models on different user machines; shipping a fixed list would either be wrong on most installs or require constant releases just to track local model availability.
- **Runtime discovery for all four providers** — Rejected: Anthropic and OpenAI publish stable model lists that benefit from compile-time type checking; calling their model-listing endpoints on every session adds latency and a new failure mode for no benefit.
- **Single JSON file shipped with the extension** — Rejected: Solves neither half of the problem cleanly: cloud lists lose type-checking; local lists still need runtime discovery to be correct per-install.

## Consequences

- Cloud users get type-checked model lists with capability flags validated at build time.
- Local users get a model list that reflects what they actually have installed.
- Discovery failures degrade gracefully — the locked default is always present even if discovery returns nothing.
- Adding a new cloud model is a typed code change with full IDE assistance; adding a new local model requires no extension change at all.

**Risks accepted:**
- Two code paths for model listing increase surface area; contract tests must verify both paths satisfy the same `ProviderProfile.listModels()` interface.
- Discovery endpoints can fail; the orchestrator must handle empty/error results gracefully (currently mitigated by always including the locked default).
- Local discovery requires network access to localhost; sandboxed environments that block this will see only the locked default.

## Guard Rails

> ⚠️ Do not introduce a static const model table for `lmstudio` or `ollama` (beyond the locked-default fallback in Slice 2).

> ⚠️ Do not rely on runtime discovery for `openai` or `anthropic`; their lists are part of the build.

> ⚠️ Do not let a discovery failure remove the locked default from the resolved list — the default must always be reachable.

> ⚠️ Do not cache discovered model lists indefinitely; future slices must implement an explicit TTL and refresh semantics.
