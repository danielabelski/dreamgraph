# ADR-195: Standardize repository release identity on DreamGraph v10.0.1

**Date:** 2026-05-16T08:08:49.904Z  
**Status:** accepted  
**Decided by:** collaborative  
**Affected entities:** package.json, package-lock.json, explorer/package.json, explorer/package-lock.json, extensions/vscode/package.json, extensions/vscode/package-lock.json, packages/host/package.json, packages/sdk/package.json, README.md, INSTALL.md, guide/02-installation.md, extensions/vscode/README.md, docs/architecture.md, docs/sdk/plugin-developer-guide/00-index.md, docs/sdk/plugin-reference/00-index.md, plans/CLI_REFERENCE.md, scripts/build-plugin-docs.ps1, src/cli/dg.ts, src/cli/utils/mcp-call.ts, extensions/vscode/src/mcp-client.ts, extensions/vscode/src/extension.ts, extensions/vscode/src/prompts/architect-core.ts, extensions/vscode/prompts/architect_core.md, RELEASE_NOTES_v10.0.0.md  

## Context

The repository release identity needed to advance from DreamGraph v10.0.0 to v10.0.1 across package manifests, client identifiers, CLI banners, extension metadata, documentation, and release notes so distributed surfaces report a consistent patch release.

**Constraints:**
- Keep release codename Renata unchanged.
- Update user-visible and package-manager-visible version surfaces consistently across root, CLI, daemon-facing clients, dashboard/explorer, architect prompt assets, and documentation.
- Do not reinterpret historical ADR references describing the v10.0.0 cutover as release-process architecture changes in this pass.
- Preserve buildability after the version bump.

## Decision

Apply a repository-wide patch release update from 10.0.0 to 10.0.1 on active package manifests, lockfiles, CLI/client version identifiers, architect prompt/version strings, and primary docs/readmes while keeping historical architectural cutover references intact unless they are part of active release identity text.

### Alternatives Considered

- **Leave versions mixed across manifests, CLI, extension, and docs** — Rejected: Inconsistent release identity causes packaging confusion, mismatched client metadata, and inaccurate user documentation.
- **Rename all historical v10.0.0 cutover references in plans/ADR-oriented files** — Rejected: Those references describe past architectural milestones rather than the active shipped patch identity, and broad historical rewrites would add noise and risk.

## Consequences

- Published package and documentation surfaces report DreamGraph v10.0.1 consistently.
- CLI and MCP client identifiers align with the current patch release.
- Release notes and installation guidance reflect the new patch version.

**Risks accepted:**
- Generated artifacts or less-central docs not included in the active patch list may still mention 10.0.0.
- Blind string replacement may touch non-release literals that coincidentally equal 10.0.0.

## Guard Rails

> ⚠️ Verify builds after the edit pass.

> ⚠️ Treat historical cutover/ADR references as documentation of past events unless they are part of active version identity.

> ⚠️ Keep codename Renata unchanged for this patch release.
