# ADR-163: Slice 6 — Two co-equal operational modes: sparse-mode best-in-class on day one, graph-amplified additive over time, never falling

**Date:** 2026-05-09T22:14:05.858Z  
**Status:** accepted  
**Decided by:** collaborative  
**Affected entities:** extensions/vscode/src/architect-v2/capabilities/matrix.ts, extensions/vscode/src/architect-v2/capabilities/density.ts, extensions/vscode/src/architect-v2/capabilities/selection.ts, extensions/vscode/src/architect-v2/capabilities/enrichment.ts, extensions/vscode/src/architect-v2/capabilities/index.ts, plans/ARCHITECT_V2_SLICE6_CAPABILITY_MATRIX.md  

## Context

Without an explicit two-mode contract the architect either gates on graph bootstrap (useless on day one) or treats sparse-mode as degraded (loses parity with generic agents and breaks never-fall invariant).

**Constraints:**
- Sparse-mode must reach parity with generic agents on day-zero install
- Graph-amplified mode is strictly additive, never a precondition
- No selection path may produce pass-level failure; worst case is per-capability gap
- Every operation, even sparse-mode, records back to the graph

## Decision

Architect v2 has exactly two operational modes at the capability layer, both first-class. (1) Sparse-mode (secondary, never failing) used when density is partial/sparse/absent AND fallback exists; uses Slice-4 T4/T5 fallback intents immediately; card carries graphBound='no'|'partial'; enrichment task queued. (2) Graph-amplified (primary) used when density is rich; mandatory graph-first path; fallback forbidden. Third state is not a mode but a declared gap: graphOnly capability + absent/sparse density => skipped with explicit gap note; pass continues. Hard invariant: no capability can fall.

### Alternatives Considered

- **Single mode with graph-first only and hard failure when graph is sparse** — Rejected: Makes day-zero install useless; breaks never-fall invariant
- **Sparse-mode as a degraded fallback (Round 1 framing)** — Rejected: Round 2 directive escalated sparse-mode to co-equal first-class
- **Block on scan_project before serving any capability** — Rejected: Gates architect on long-running graph bootstrap; breaks parity with generic agents

## Consequences

- Brand-new install ships fully working coding agent at parity with generic agents
- Graph-amplified mode is strictly additive over time
- No Slice 6 selection path produces pass-level failure
- Slice 5 cards must render graphBound pill (yes|partial|no|gap)
- Slice 7 must consume enrichmentQueue and respect skippable graphOnly capabilities

**Risks accepted:**
- Density thresholds mis-tuned -> over-prefer sparse-mode (mitigation: surface density on every card)
- Graph-write side effects regress -> sparse-mode never bootstraps the graph (mitigation: record-everything ADR + Slice 7 verification)
- Capability misclassified as graphOnly -> sparse installs see avoidable gaps (mitigation: review of 8 graphOnly entries)

## Guard Rails

> ⚠️ chooseCapabilityPath MUST never return a kind other than 'graph-amplified' | 'sparse-mode' | 'gap'

> ⚠️ Density 'rich' MUST produce empty allowedFallback

> ⚠️ graphOnly capability + density 'absent'|'sparse' MUST return kind='gap'

> ⚠️ Slice 6 modules MUST NOT import from architect-v2/providers, architect-v2/cards, or any v1 path

> ⚠️ No Slice 6 function may be impure
