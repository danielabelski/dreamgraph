# ADR-240: Separate API continuation envelopes from CLI execution and keep autonomous targets authoritative

**Date:** 2026-08-21T20:59:39.591Z  
**Status:** accepted  
**Decided by:** collaborative  
**Affected entities:** src/architect/routes.ts, src/architect/continuation.ts, src/architect/cli-bridge.ts, extensions/vscode/src/architect-core/adapters/codex-cli/orchestrator.ts, extensions/vscode/src/architect-core/adapters/copilot-cli/orchestrator.ts, extensions/vscode/src/autonomy.ts, extensions/vscode/src/autonomy-loop.ts, ArchitectRunResult, codex-cli, copilot-cli, native-api-tool-loop  

## Context

CLI transports had inherited native API continuation-envelope expectations, including Codex failure classification and standalone CLI prompt/result fields. Autonomous execution also treated productive checkpoint completion and status summaries as terminal even while the user-requested target remained locally actionable.

**Constraints:**
- Native API/controller continuation tokens and envelopes must remain backward compatible at the Architect route boundary.
- Codex CLI and Copilot CLI adapters must execute concrete requests and return normalized content, provenance, tool trace, timeout, cancellation, and session data without parsing or requiring Architect continuation envelopes.
- CLI session identifiers are transport/session metadata, not Architect continuation tokens.
- Autonomous execution must stop for target completion, genuine blockers, required user decisions, and explicit resource policy limits, but not merely for clean checkpoints.
- Timeout/cancellation ownership, audit, stdout purity, mutation non-replay, and adapter provenance must remain intact.

## Decision

Continuation-envelope semantics belong to the native API adapter/controller boundary and are not part of the CLI adapter contract. Controllers may project continuation-derived intent into neutral concrete execution tool requirements before invoking a CLI. CLI results are normalized as ordinary executions, after which the controller evaluates task completion. Intermediate slice/checkpoint completion does not terminate autonomous execution while the user-requested completion target remains incomplete and locally actionable.

### Alternatives Considered

- **Keep a shared continuation manifest on every adapter** — Rejected: It leaks API protocol mechanics into CLI transports and makes successful CLI execution depend on an unrelated envelope format.
- **Add an unconditional continue=true flag** — Rejected: It cannot distinguish target completion, user decisions, blockers, policy budgets, or locally actionable remaining work.
- **Treat every CLI session id as a continuation token** — Rejected: Transport session identity does not encode Architect task completion or API continuation semantics.

## Consequences

- Codex and Copilot CLI executions succeed without architect_continuation fields.
- Standalone CLI prompts and bridge result contracts expose neutral execution requirements rather than continuation metadata.
- Native API continuation parsing, tokens, and controller route behavior remain available.
- Autonomous mode continues after intermediate checkpoints and verification when actionable requested work remains.
- External maintenance timeouts do not terminate unrelated locally actionable implementation.

**Risks accepted:**
- Text-derived task-state hints can be ambiguous until more controller-owned structured completion evidence is available.
- Route compatibility fields still need regression coverage so external clients keep receiving native continuation state where appropriate.
- Autonomous loops still depend on explicit pass/time budgets when those policies are configured.

## Guard Rails

> ⚠️ Do not require, parse, synthesize, persist, or expose Architect continuation envelopes or tokens in CLI adapter contracts.

> ⚠️ Do not classify a successful CLI execution as failed because assistant prose lacks an Architect continuation envelope.

> ⚠️ Do not treat CLI session IDs or process handles as Architect continuation tokens.

> ⚠️ Do not terminate autonomous execution solely because a slice, checkpoint, verification step, or status summary completed.

> ⚠️ Do not auto-continue when the requested target is complete, user input is genuinely required, scope must expand, a genuine external blocker exists, or an explicit policy budget requires stopping.

> ⚠️ Keep native API continuation semantics and route-boundary compatibility owned above CLI adapters.
