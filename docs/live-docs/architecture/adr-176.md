# ADR-176: ContextBuilder routes requirements to graph or fallback sources with provenance

**Date:** 2026-05-09T23:33:09.188Z  
**Status:** accepted  
**Decided by:** collaborative  
**Affected entities:** extensions/vscode/src/architect-v2/context/builder.ts, extensions/vscode/src/architect-v2/context/fallback-signals.ts, extensions/vscode/src/architect-v2/orchestrator/types.ts  

## Context

ADR-174 split prompt assembly into 'composer declares' and 'assembler fulfills'. But declaring is cheap; *fulfilling* must work in every realistic project state \u2014 fully indexed, partially indexed, sparse, and not indexed at all. A naive assembler that just queries the graph degrades to 'empty prompt' in sparse mode (ADR-173) and silently loses provenance about why a section was missing.

**Constraints:**
- FallbackSignalProvider methods MUST be safe to call when no workspace is open — return empty results, never throw. NullFallbackSignalProvider satisfies this trivially.
- Every ContextSection emitted by DefaultContextBuilder MUST carry provenance.
- Sections produced via fallback for a graph-shaped requirement MUST set provenance.fallbackReason to one of {graph_sparse, graph_absent, graph_error}.
- ContextEnvelope.unmetRequirements MUST be populated for every requirement the builder could not satisfy.
- FallbackSignalProvider lives in context/ and MUST NOT import from orchestrator/project-graph (no graph types leak into the fallback path).

## Decision

Two-source assembler with provenance. DefaultContextBuilder routes each declared requirement to one of two sources: ProjectGraphReader for graph-shaped kinds (architectural_decisions, adr_lineage, unresolved_blockers, prior_failed_attempts, graph_neighborhood) and a new FallbackSignalProvider port for non-graph kinds (file_excerpts, recent_history, runtime_diagnostics, environment_state). When the graph reader reports 'sparse' or 'absent' richness for a graph-shaped requirement, the builder transparently substitutes the FallbackSignalProvider (shallow project walk + file excerpts of any anchors) and stamps the section with provenance recording the fallback reason. Every emitted ContextSection carries SectionProvenance {requirementKind, signalSource, fallbackReason?}. Requirements the assembler could not satisfy are listed in ContextEnvelope.unmetRequirements with a typed reason. The composer renders whatever it gets without retry.

### Alternatives Considered

- **Hard-fail when graph is sparse — surface a BlockerCard.** — Rejected: Punishes day-1 installs and projects not yet indexed; sparse-mode is a designed mode (ADR-173).
- **Have the composer pick a different prompt template when graph is sparse.** — Rejected: Couples cognition to rendering and forces the composer to know graph state — violates ADR-174.
- **Single mega-port that bundles graph + filesystem + diagnostics.** — Rejected: Hides where each signal came from; provenance unrecoverable; tests cannot stub one source without the other.
- **Fall back silently with no provenance.** — Rejected: Composer/audit cannot distinguish 'graph-amplified context' from 'shallow filesystem walk'; metrics get noisy.

## Consequences

- Day-1 installs (no graph indexed) get useful context via filesystem + diagnostics; the same prompt template runs.
- When the graph is later populated, the same builder returns graph-amplified sections with no code change in composer or orchestrator.
- Audit + future metrics can compute 'graph hit rate' per requirement kind directly from provenance.
- Tests for the builder need only stub two ports (graph reader + fallback) to exercise every code path.

**Risks accepted:**
- Two source paths drift in capability over time. Mitigation: same DefaultContextBuilder dispatches to both; tests cover both with the same fixture set.
- Provenance bloats envelope size. Mitigation: provenance is a small fixed-shape record (3 strings); negligible compared to content.
- Fallback for graph-shaped requirements becomes the default because graph stays sparse. Mitigation: provenance is observable; future metrics surface chronic fallback rates.

## Guard Rails

> ⚠️ Test (8A.5 or earlier): assembler called with NullProjectGraphReader + NullFallbackSignalProvider must return a non-throwing envelope with sections.length === 0 and unmetRequirements.length === manifest.requirements.length.

> ⚠️ Build-time check (Slice 8B): grep that fails if context/*.ts imports from /^(vscode|fs|node:|http|mcp_)/ — the builder is a pure dispatcher; transport adapters live under orchestrator/adapters/.

> ⚠️ Provenance assertion: a unit test reads every emitted section in a representative envelope and asserts provenance is set.
