# ADR-131: SDK webhooks are core service first and plugin-consumable later

**Date:** 2026-05-08T11:23:46.381Z  
**Status:** accepted  
**Decided by:** human  
**Affected entities:** plans/DREAMGRAPH_SDK_ROADMAP.md, sdk:webhooks, plugin-sdk:webhook-consumption  

## Context

The SDK roadmap needed to decide whether webhooks should be implemented as plugin-provided functionality or as a core DreamGraph service before plugins consume webhook capabilities.

**Constraints:**
- Webhook delivery touches secrets, signing, retries, dead-letter queues, replay, and operator trust.
- Plugin code must not receive broad authority over delivery security or operational reliability by default.
- The plugin SDK should expose stable consumable capabilities only after the core service defines the trust and operational model.

## Decision

Implement webhook delivery as a core service first. Make it plugin-consumable later through host-mediated capabilities once delivery, signing, retry, DLQ, replay, and audit semantics are mature.

### Alternatives Considered

- **Let plugins implement webhook delivery directly in MVP** — Rejected: Would delegate secrets, signing, retries, replay, and failure handling to arbitrary plugins before the trust model is established.
- **Exclude webhooks entirely from the plugin roadmap** — Rejected: Plugins are expected to benefit from webhook events later, but they should consume a core service rather than own delivery.

## Consequences

- Core owns webhook security and delivery semantics.
- Plugins can later subscribe to or emit webhook-relevant events through a constrained host-mediated API.
- The MVP plugin surface remains smaller and safer.

**Risks accepted:**
- Core webhook implementation may become a bottleneck for plugin-driven integrations.
- The later plugin-consumable API must avoid leaking secrets or replay authority.

## Guard Rails

> ⚠️ Do not grant plugins arbitrary webhook delivery authority before the core webhook service exists.

> ⚠️ Do not store signing secrets or retry/DLQ policy inside untrusted plugin packages.

> ⚠️ Do not expose webhook replay or delivery mutation operations to plugins without explicit host-mediated authorization.
