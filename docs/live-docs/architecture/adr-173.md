# ADR-173: Sparse / no-graph operation is a first-class mode via Null ports

**Date:** 2026-05-09T22:54:59.756Z  
**Status:** accepted  
**Decided by:** collaborative  
**Affected entities:** extensions/vscode/src/architect-v2/orchestrator/loop.ts, extensions/vscode/src/architect-v2/orchestrator/project-graph.ts  

## Context

If the orchestrator's behavior degrades to 'broken' or 'mostly empty' when no graph backend is wired, the Architect becomes useless for day-1 installs, for projects DreamGraph hasn't indexed yet, and for hosts that don't run DreamGraph at all. The 'graph-native' framing must not become 'graph-required'.

**Constraints:**
- NullProjectGraphReader and NullProjectGraphRecorder live in orchestrator/project-graph.ts and MUST remain importable by tests without pulling in any backend.
- ContextBuilder (8A.3) MUST produce a non-empty, useful ContextEnvelope when Reader returns NULL_PROJECT_SUBGRAPH — by falling back to filesystem/runtime/LSP signals — not a near-empty 'no graph available' envelope.
- BlockerCards must NEVER cite 'graph not wired' as a blocker reason. The graph not being wired is not a failure.

## Decision

Sparse / no-graph operation is a first-class supported mode. The orchestrator wires NullProjectGraphReader (returns 'absent' richness, empty subgraphs) and NullProjectGraphRecorder (no-op writes) by default. runPass executes the same sequence regardless of backend presence: density measurement returns 'absent' \u2192 Slice 6 sparse-mode kicks in \u2192 ContextBuilder reconstructs context from filesystem/runtime/LSP signals \u2192 the user gets a useful pass. When a real Reader and Recorder are wired (e.g. the DreamGraph adapter in 8A.3/8A.4), the same loop produces graph-amplified passes. Cards are still emitted in sparse mode; they are simply not durably indexed when the Recorder is the null implementation.

### Alternatives Considered

- **Throw / surface a 'graph backend missing' blocker when no Reader is wired.** — Rejected: Punishes the user for the host's setup choice; turns sparse-mode (a designed operating mode) into an error.
- **Auto-detect 'no graph' and switch to a different code path inside runPass.** — Rejected: Branching on backend presence is exactly the coupling ADR-171 forbids; the loop must look identical regardless of who's behind the port.
- **Refuse to run without a Recorder; force every host to wire one.** — Rejected: Defeats the point of having an Architect that works on day 1 in any project.

## Consequences

- Day-1 install in any project (no DreamGraph indexing, no prior cards) yields a working Architect with reduced-but-real cognition.
- Unit tests of the orchestrator can use the null ports directly without scaffolding a backend.
- The DreamGraph adapter (8A.3/8A.4) becomes one optional enhancement among many possible backends, not a precondition for the Architect to function.

**Risks accepted:**
- Sparse-mode quality silently regresses because nobody tests it. Mitigation: dedicated NullPorts test in the verification harness.
- ContextBuilder's sparse-mode path becomes a second implementation of context assembly, drifting from the graph-mode path. Mitigation: same ContextBuilder consumes the same Reader port; only the *content* of the subgraph changes.

## Guard Rails

> ⚠️ A test (added in 8A.3 or 8A.4) drives a full pass with NullProjectGraphReader + NullProjectGraphRecorder and asserts the resulting PassResult contains at least one Card and a non-error CompletionStatus.

> ⚠️ ContextBuilder sub-slice plan must explicitly enumerate its sparse-mode signal sources (filesystem walk, LSP queries, runtime probes, recent diagnostics).
