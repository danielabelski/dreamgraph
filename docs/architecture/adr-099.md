# ADR-099: Progressive ADR enforcement (advisory → soft → strict)

**Date:** 2026-05-03T10:27:16.749Z  
**Status:** accepted  
**Decided by:** human  
**Affected entities:** src/cognitive/normalizer.ts, src/tools/record-architecture-decision.ts, extensions/vscode/src/context-builder.ts, extensions/vscode/prompts/architect_core.md, adr_log.json  

## Context

ADRs are currently paper. discoverAndRecordADRs() is never invoked, the normalizer has no ADR guard rails, and the architect only consults ADRs when the user prompt matches a regex. Code changes can silently violate accepted ADRs. Hard-blocking by default would create user resentment and obstruct legitimate exception cases.

**Constraints:**
- Humans must always retain manual override capability
- Default behavior must build trust, not friction
- Teams with stricter policy needs must have an opt-in escalation path
- Enforcement level must be configurable per instance

## Decision

Three progressive levels controlled by DREAMGRAPH_ADR_ENFORCEMENT=advisory|soft|strict (default: advisory). Advisory: log warning, create tension signal, explain violation risk in architect response — no blocking. Soft (workspace opt-in): architect surfaces a confirmation prompt before proceeding ("This conflicts with ADR-004. Proceed anyway? [yes/no]"). Strict (team setting): blocks AUTONOMOUS promotion only — normalizer refuses to promote ADR-violating edges and architect refuses to apply ADR-violating patches without an explicit manual override gesture. Humans may always override manually at every level.

### Alternatives Considered

- **Hard-block by default** — Rejected: Generates friction faster than it generates value; obstructs legitimate exception cases.
- **Pure advisory only (no strict path)** — Rejected: Insufficient for teams with formal architecture compliance requirements.
- **Per-ADR enforcement level** — Rejected: Configuration sprawl; project-wide policy is the right granularity for this version.

## Consequences

- ADRs become enforceable instead of decorative
- Default advisory mode builds user trust by explaining rather than blocking
- Soft mode adds friction only proportional to risk
- Strict mode satisfies team policy without locking out human judgment
- Per-instance config keeps the choice local to project risk tolerance

**Risks accepted:**
- Soft-mode confirmation prompts may be ignored / clicked through habitually
- Strict mode could surprise users who didn't realize an ADR was in effect
- Tension signals from advisory mode could create alert fatigue

## Guard Rails

> ⚠️ Manual human override MUST work at every enforcement level

> ⚠️ Default level MUST remain advisory — never escalate by default

> ⚠️ Strict mode MUST only block autonomous promotion, never block humans

> ⚠️ DREAMGRAPH_ADR_ENFORCEMENT env var name MUST NOT change without migration notes
