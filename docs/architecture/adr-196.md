# ADR-196: Provider-neutral workspace snapshot tracking for pending change review

**Date:** 2026-05-16T09:16:55.005Z  
**Status:** accepted  
**Decided by:** collaborative  
**Affected entities:** extensions/vscode/src/change-review-service.ts, extensions/vscode/src/chat-panel.ts, extensions/vscode/src/tool-classification.ts, extensions/vscode/src/reviewable-file-filter.ts  

## Context

The Copilot-style pending diff Keep/Undo UI is provider-neutral, but opaque write tools can mutate workspace files without calling ChangeReviewService per-file hooks, leaving no pending reviews to render.

**Constraints:**
- Do not tie review tracking to Copilot-specific adapters or providers.
- Cover local, MCP/daemon, and future tool execution paths from a common boundary.
- Avoid noisy/generated files by reusing existing reviewable-file filtering.
- Preserve explicit per-file tracking paths that already exist.
- Keep the first implementation simple enough to patch at the known chat-panel tool execution loop.

## Decision

Add provider-neutral workspace snapshot support to ChangeReviewService and wrap classified write tool execution in the common chat-panel tool loop. Before an isWriteToolName-classified tool runs, snapshot reviewable workspace files; after the tool finishes, detect changed/created/deleted files, register pending reviews, and post pending reviews to the UI.

### Alternatives Considered

- **Wrap Copilot CLI HOST_FS/writeFile** — Rejected: It would tie the feature to Copilot and miss MCP/local/future write paths.
- **Only rely on local-tools explicit captureBeforeWrite/recordAfterWrite hooks** — Rejected: Opaque daemon/MCP write tools bypass those hooks, so UI remains empty for common flows.
- **Use VS Code file watchers only** — Rejected: Watchers are asynchronous and harder to correlate with tool execution and before-content snapshots.

## Consequences

- Pending diff UI can be populated for any provider-neutral write tool path.
- Existing local tool explicit hooks remain compatible.
- Some write tools will incur bounded workspace scan overhead.
- Future providers can benefit without adapter-specific code.

**Risks accepted:**
- Large workspaces may make full snapshots expensive.
- If filtering is too broad, generated files may appear in pending reviews.
- If filtering is too narrow, relevant edits may be missed.
- Deleted-file handling must avoid crashing when after-content is unavailable.

## Guard Rails

> ⚠️ Use ReviewableFileFilter when selecting snapshot candidates.

> ⚠️ Only run snapshots for tools classified by isWriteToolName.

> ⚠️ Keep Copilot-specific adapters unchanged.

> ⚠️ Post pending reviews after write tool execution completes.

> ⚠️ Preserve captureBeforeWrite/recordAfterWrite APIs for explicit paths.
