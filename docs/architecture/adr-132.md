# ADR-132: Plugin management is bundled into the existing dg CLI

**Date:** 2026-05-08T11:23:46.405Z  
**Status:** accepted  
**Decided by:** human  
**Affected entities:** plans/DREAMGRAPH_SDK_ROADMAP.md, cli:dg, cli:dg plugin, plugin-sdk:management  

## Context

The SDK roadmap needed to decide whether plugin management should use a separate toolchain or become part of the existing DreamGraph command-line interface.

**Constraints:**
- Plugin management is instance administration.
- Operators should not need a separate plugin-specific CLI toolchain for normal administration.
- The existing dg CLI is the natural administrative surface for DreamGraph instances.

## Decision

Bundle plugin management commands into the existing dg CLI under dg plugin rather than creating a separate CLI.

### Alternatives Considered

- **Create a standalone plugin CLI** — Rejected: Would split instance administration across multiple tools and increase operator burden.
- **Leave plugin management entirely manual** — Rejected: Would undermine repeatable installation, inspection, enabling, disabling, and lifecycle management.

## Consequences

- Operators administer plugins through the same dg tool used for the rest of DreamGraph.
- Documentation and automation can standardize on dg plugin commands.
- Future plugin lifecycle commands should fit under the existing CLI command hierarchy.

**Risks accepted:**
- The dg CLI can become crowded if plugin commands are not organized carefully.
- CLI implementation must preserve clear separation between plugin administration and runtime plugin authority.

## Guard Rails

> ⚠️ Do not introduce a separate first-party plugin management CLI without superseding this decision.

> ⚠️ Keep plugin lifecycle administration under dg plugin or a clearly compatible dg subcommand hierarchy.

> ⚠️ Do not let CLI convenience bypass plugin trust, signing, allowlist, or capability checks.
