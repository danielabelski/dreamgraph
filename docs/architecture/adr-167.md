# ADR-167: Slice 7 — Verification planner is a frozen capability->verifications table; planVerifications is pure

**Date:** 2026-05-09T22:30:26.704Z  
**Status:** accepted  
**Decided by:** collaborative  
**Affected entities:** extensions/vscode/src/architect-v2/verification/planner.ts, extensions/vscode/src/architect-v2/verification/types.ts, plans/ARCHITECT_V2_SLICE7_VERIFICATION.md  

## Context

Without a frozen capability->verification table, verification logic spreads across imperative branches and the 'every code change should attempt relevant verification' goal becomes unauditable. Read-only capabilities would also waste budget on irrelevant build/test runs.

**Constraints:**
- Table must cover every CapabilityId (TypeScript Record<CapabilityId, PlanEntry> exhaustiveness)
- Verification capabilities (verify.*) map to NONE to prevent infinite recursion
- planVerifications is pure: no I/O, no Date.now, no random
- Failed mutations short-circuit to empty plan; classifier produces mutation_failed status

## Decision

VERIFICATION_PLAN_TABLE is a frozen Record<CapabilityId, PlanEntry> covering every Slice-6 CapabilityId exhaustively (TypeScript compile gate). planVerifications(capabilityId, mutationOutcome) is pure: returns empty plan for failed mutations and for read-only/env-IO capabilities; returns the table's entry otherwise. VERIFICATION_PERFORMED_BY maps each VerificationKind to its Slice-6 verifier capability so the orchestrator can route through Slice 6 selection without coupling planner to capability internals.

### Alternatives Considered

- **Switch statement per CapabilityId in planner** — Rejected: 42 capabilities -> 42 arms; impossible to audit against the plan §1 table
- **Configurable per-project verification rules** — Rejected: Premature; provider-neutral defaults must work first; per-project overrides can be additive later
- **Always run all verifications regardless of capability** — Rejected: Wastes budget on read-only operations; conflicts with token economy goal

## Consequences

- Adding a CapabilityId is a single table entry + one classifier branch (compile error otherwise)
- Read-only operations skip verification entirely (token economy preserved)
- Mutations always have type+build attempted (catches regressions immediately)
- Markdown mutations route to lint not build (correct cost profile)
- Graph mutations route to discipline+invariant (preserves graph invariants)

**Risks accepted:**
- Table grows stale if a capability changes verification needs (mitigated by ADR-164 same-commit guard rail extension)
- Markdown projects without a markdown linter see 'verification_unavailable' (acceptable: surfaced as typed status, not a failure)

## Guard Rails

> ⚠️ VERIFICATION_PLAN_TABLE MUST stay Object.freeze'd; no runtime mutation

> ⚠️ Adding a CapabilityId requires updating VERIFICATION_PLAN_TABLE in the same commit

> ⚠️ verify.* capabilities MUST map to NONE (no recursive verification)

> ⚠️ planVerifications MUST stay pure (no I/O, no Date.now, no random)
