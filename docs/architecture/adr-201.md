# ADR-201: Copilot CLI is a native DreamGraph Architect adapter

**Date:** 2026-05-19T21:12:44.950Z  
**Status:** accepted  
**Decided by:** collaborative  
**Affected entities:** copilot-cli, codex-cli, CliAgentAdapter, ArchitectRunRequest, ArchitectRunResult, ArchitectPassEnvelope, DreamGraph MCP server, ContextBuilder, BudgetCoordinator, ContextInspector, extensions/vscode/src/architect-core/adapters/copilot-cli/provider-port.ts, extensions/vscode/src/architect-core/adapters/copilot-cli/orchestrator.ts, extensions/vscode/src/architect-core/adapters/copilot-cli/argv.ts, extensions/vscode/src/architect-core/adapters/copilot-cli/event-stream.ts  

## Context

Copilot CLI integration has moved from a dumb provider subprocess bridge to a DreamGraph-native Architect adapter. The architecture needs to preserve this as a first-class adapter decision and make the reusable pattern available for future CLI adapters such as Codex CLI without copying provider-specific implementation details into Architect core.

**Constraints:**
- Architect core must remain provider-neutral and continue to exchange normalized ArchitectRunRequest, ArchitectRunResult, and ArchitectPassEnvelope contracts.
- DreamGraph MCP grounding remains the authoritative source for repository facts and graph operations during Copilot CLI runs.
- Copilot-specific prompt composition, MCP bridge readiness, event parsing, and process behavior must stay inside the Copilot CLI adapter/provider boundary.
- The adapter must preserve context economy controls, current-turn isolation, live tool trace normalization, and Context Inspector diagnostics.
- Future Codex CLI reuse should extract principles and shared adapter seams, not blindly clone Copilot CLI provider details.

## Decision

Treat Copilot CLI as a native DreamGraph Architect adapter: it participates in graph-grounded runs, bounded context assembly, DreamGraph MCP authority checks, normalized live event/tool-trace streaming, prompt-file fallback, and Context Inspector observability while keeping provider-specific mechanics adapter-local. Use this adapter as the reference pattern for a future Codex CLI native adapter, reusing the architecture principles and shared seams while respecting Codex-specific CLI configuration, sandboxing, event, and MCP behavior.

### Alternatives Considered

- **Keep Copilot CLI as a dumb subprocess bridge with only prompt-in/text-out behavior** — Rejected: That would lose DreamGraph authority semantics, context-economy enforcement, MCP readiness checks, live tool traces, and inspectable adapter provenance.
- **Move Copilot CLI behavior into Architect core** — Rejected: That would contaminate provider-neutral Architect contracts with provider-specific CLI transport, prompt, and event-stream details.
- **Clone Copilot CLI implementation directly for Codex CLI** — Rejected: Codex CLI has different configuration, sandbox/approval, and event semantics; only the native-adapter principles and normalized seams should be reused.

## Consequences

- Copilot CLI is treated as a first-class DreamGraph Architect execution path rather than a generic CLI wrapper.
- Graph-grounded answers can fail closed when DreamGraph MCP bridging is unavailable or untrusted.
- Live Copilot CLI output remains observable through normalized chat/tool trace surfaces and compact Context Inspector diagnostics.
- The Codex CLI adapter can follow the same native-adapter principle with lower architectural risk, while adapting to Codex-specific runtime semantics.
- Architect core remains clean because provider-specific logic stays behind adapter/provider boundaries.

**Risks accepted:**
- Future Copilot CLI output, MCP, or prompt-file behavior may change and require adapter updates.
- Reference reuse for Codex CLI may accidentally overfit to Copilot-specific assumptions if not reviewed against Codex behavior.
- Native adapter complexity is higher than a simple subprocess wrapper and requires stronger verification around context, tool authority, and streaming.

## Guard Rails

> ⚠️ Do not regress Copilot CLI back to a dumb prompt-in/text-out subprocess bridge without revisiting this ADR.

> ⚠️ Do not move Copilot-specific prompt serialization, MCP config, event parsing, or process control into provider-neutral Architect core.

> ⚠️ Do not implement Codex CLI by blindly copying Copilot CLI internals; reuse the native-adapter principles and normalized seams while validating Codex-specific behavior.

> ⚠️ Do not allow Copilot CLI runs to satisfy graph-grounded repository claims without DreamGraph MCP grounding or equivalent authoritative validation.

> ⚠️ Keep Context Inspector diagnostics and normalized tool traces available for native CLI adapter runs.
