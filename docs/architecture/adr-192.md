# ADR-192: V1 hybrid chat panel is the canonical VS Code architect surface; architect-v2 remains quarantined

**Date:** 2026-05-11T21:40:04.172Z  
**Status:** accepted  
**Decided by:** collaborative  
**Affected entities:** feature_vscode_extension_runtime, dreamgraph_extensions_vscode_src, workflow_vscode_chat_context_loop  

## Context

The extension contains both the shipping V1 hybrid architect/chat surface and a retained architect-v2 prototype tree, creating risk that future changes may accidentally reactivate or split product behavior across competing orchestration paths.

**Constraints:**
- The currently working Extension Host UI and command surface are wired through extension.ts, commands.ts, chat-panel.ts, architect-llm.ts, and context-builder.ts.
- The codebase intentionally retains architect-v2 sources for historical reference.
- Future contributors and agents need guard rails to avoid re-importing quarantined code without explicit review.

## Decision

Treat the V1 hybrid stack (ChatPanel + ArchitectLlm + ContextBuilder + autonomy loop + webview helpers) as the only canonical VS Code architect surface in v10.0.0. Keep architect-v2 quarantined as non-activated historical reference unless a new ADR explicitly replaces the canonical surface.

### Alternatives Considered

- **Re-enable architect-v2 alongside V1** — Rejected: Would fragment the UX, duplicate orchestration seams, and increase risk of drift between command, reporting, and continuation behavior.
- **Delete architect-v2 immediately** — Rejected: Historical reference and migration context are still useful, and current code comments intentionally preserve the tree without activating it.

## Consequences

- Future work should extend the V1 hybrid path rather than adding parallel activation paths.
- Command and webview debugging can focus on ChatPanel and related V1 modules.
- Quarantined prototype code remains available for reference without affecting runtime behavior.

**Risks accepted:**
- Contributors may still edit quarantined code assuming it is live.
- The retained prototype tree can create cognitive overhead during code search.

## Guard Rails

> ⚠️ Do NOT import or register architect-v2 modules from extension.ts without a new superseding ADR.

> ⚠️ Do NOT add command palette or webview entry points that bypass ChatPanel as the canonical architect surface.

> ⚠️ When documenting architect runtime behavior, anchor claims to extension.ts, chat-panel.ts, architect-llm.ts, and context-builder.ts unless a new ADR changes the seam.
