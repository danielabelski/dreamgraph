# ADR-198: Copilot CLI adapter uses bounded prompt-file context injection

**Date:** 2026-05-19T20:53:50.037Z  
**Status:** accepted  
**Decided by:** collaborative  
**Affected entities:** extensions/vscode/src/architect-core/adapters/copilot-cli/argv.ts, extensions/vscode/src/architect-core/adapters/copilot-cli/orchestrator.ts, extensions/vscode/src/architect-core/adapters/copilot-cli/provider-port.ts, extensions/vscode/src/chat-panel.ts, extensions/vscode/src/context-inspector.ts, BudgetCoordinator, ContextBuilder, ArchitectRunRequest, ArchitectPassEnvelope, copilot-cli  

## Context

The Copilot CLI adapter must pass DreamGraph Architect context to a subscription CLI without overflowing command-line limits or letting provider-specific prompt assembly leak into Architect core. Earlier file-level ADR exports were not accurate enough for this adapter-specific context-economy decision.

**Constraints:**
- Architect core remains normalized around ArchitectRunRequest, ArchitectRunResult, and ArchitectPassEnvelope; Copilot-specific prompt serialization is adapter-private.
- The CLI invocation must stay reliable on Windows and other shells with finite argv length limits.
- Prompt construction must preserve the current-turn marker contract and bounded chat history so the model responds only to the active user request while retaining enough prior context.
- DreamGraph MCP grounding remains authoritative for repository facts; serialized prompt context is a transport envelope, not a replacement for MCP graph queries.
- Prompt-size diagnostics must be observable through Context Inspector output.

## Decision

Keep Copilot CLI prompt composition inside the Copilot adapter/provider boundary, build the Architect envelope with context-economy controls, retain a bounded history window, mark the current turn explicitly, and fall back to a temporary prompt.md file when the serialized prompt exceeds the safe argv byte budget. Surface prompt byte count, history count, advertised MCP server/tool count, current-turn marker status, and model selection to the Context Inspector.

### Alternatives Considered

- **Pass the full prompt exclusively through argv** — Rejected: Large Architect prompts can exceed shell or process argument limits, especially on Windows, and fail before Copilot CLI starts.
- **Move Copilot prompt serialization into Architect core** — Rejected: That would contaminate provider-neutral core contracts with a provider-specific CLI transport concern.
- **Rely only on MCP tools and omit serialized task/history context** — Rejected: The CLI still needs the concrete current turn, autonomy/reporting contracts, and bounded conversation context before it can decide which MCP tools to call.

## Consequences

- Copilot CLI runs remain reliable for large Architect prompts by using prompt.md file fallback above the adapter's argv budget.
- Context Inspector can explain why a run used a file-backed prompt and how much context was serialized.
- Architect core remains provider-neutral while Copilot-specific transport policy stays adapter-local.
- The current-turn marker and bounded history reduce stale-context responses and prompt bloat.

**Risks accepted:**
- Prompt file lifecycle bugs could leave stale temporary prompt artifacts or point a run at the wrong content.
- A provider CLI change in accepted prompt-file invocation semantics could require adapter updates.
- Plain byte-count logging is less structured than shared budget-component telemetry unless separately integrated with BudgetCoordinator summaries.

## Guard Rails

> ⚠️ Do not move Copilot CLI prompt serialization or prompt.md fallback into provider-neutral Architect core.

> ⚠️ Do not remove the explicit current-turn marker from Copilot CLI prompts without replacing it with an equally strong active-turn isolation mechanism.

> ⚠️ Do not disable bounded history or argv byte budgeting for Copilot CLI runs.

> ⚠️ Do not treat serialized prompt context as authoritative graph truth; repository facts still require DreamGraph MCP grounding.
