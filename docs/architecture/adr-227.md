# ADR-227: Architect plugin browser API is a versioned daemon projection

**Date:** 2026-05-31T15:29:00.798Z  
**Status:** accepted  
**Decided by:** collaborative  
**Affected entities:** standalone-architect, feature_plugin_runtime, src/architect/routes.ts, src/plugins/architect-contributions.ts, src/plugins/architect-plan-state.ts  

## Context

Standalone Architect needs to list contributed tabs, read plan-bound snapshots, and dispatch actions without embedding active plugin modules in the browser or exposing direct storage authority.

**Constraints:**
- Browser clients use versioned /api/architect/v1 daemon contracts.
- Actions are structured POST commands dispatched through active host registration.
- Sidebar summaries and badges derive from the same validated snapshot contract.
- Browser payloads must not reveal state-store paths or direct file APIs.

## Decision

Expose host-validated Architect plugin descriptors and explicit plan-bound snapshots through versioned /api/architect/v1 routes. Browser actions post structured commands to the daemon, which validates and dispatches to registered host-side handlers and returns a fresh snapshot. Sidebar summaries and badges are derived from that daemon snapshot.

### Alternatives Considered

- **Bundle active plugin modules into the browser** — Rejected: That would execute plugin code in a new trust domain and bypass the declarative host-rendered boundary.
- **Expose store paths or direct file APIs to browser code** — Rejected: That would leak implementation details and create browser-side mutation authority.
- **Let browser actions call plugin handlers directly** — Rejected: Actions must pass daemon routing, registration, scope, and schema checks.

## Consequences

- Browser rendering remains a projection over daemon-owned state.
- Action failure cases can be represented as explicit HTTP responses.
- Sidebar, badge, and tab content stay consistent because they share one snapshot contract.

**Risks accepted:**
- Route-file complexity may grow and require extraction.
- Snapshot contract versioning must remain stable as renderer kinds expand.

## Guard Rails

> ⚠️ Do not embed active plugin modules into the browser bundle.

> ⚠️ Do not expose raw state-store paths or direct file APIs.

> ⚠️ Do not allow browser actions to bypass host registration, schema validation, or explicit plan scope.

> ⚠️ Keep Architect plugin routes under the versioned daemon API contract.
