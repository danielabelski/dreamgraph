# ADR-144: Architect v2 enforces a strict 5-tier execution priority: MCP graph → MCP mutation → MCP verification → VS Code APIs → shell

**Date:** 2026-05-09T19:57:38.717Z  
**Status:** accepted  
**Decided by:** collaborative  
**Affected entities:** extensions/vscode/src/architect-v2/execution/, extensions/vscode/src/local-tools.ts, extensions/vscode/src/mcp-client.ts, plans/ARCHITECT_V2_SLICE1_INVENTORY.md  

## Context

v1 Architect's tool execution layer has implicit precedence between local extension-host tools and MCP daemon tools, with name collisions (local write_file vs MCP create_file, local read_local_file vs MCP read_source_code) and bypass points where v1 reaches for vscode.workspace.fs / vscode.workspace.findFiles when an MCP/DreamGraph tool would be the graph-first choice. Without a structural priority order, graph-first is a slogan, not an invariant.

**Constraints:**
- Graph-first principle: DreamGraph is the primary context, planning, memory, and safety boundary — reaching around it must be the exception, not the default.
- Tool selection must achieve 99.999999% reliability target with no false 'tool unavailable' aborts.
- Some operations are genuinely extension-host-only (clipboard, shell, opening editor tabs, accessing user selection) and a pure-MCP rule would be unworkable.
- Today's local tools (read_local_file, write_file, modify_entity) duplicate MCP equivalents and create collisions — must be eliminated.

## Decision

Architect v2 enforces a single execution priority order that the tool dispatcher must follow for every tool call: (1) MCP entity / API / graph queries, (2) MCP file mutation (create_file, edit_file, edit_entity, patch_markdown_chapter), (3) MCP verification + runtime senses (query_self_metrics, query_runtime_metrics, query_db_schema, etc.), (4) VS Code editor APIs (only when MCP is genuinely inappropriate or absent for the operation), (5) generic shell via run_command. The dispatcher logs the selected tier per call as machine-readable trace. Local 'duplicate' tools (read_local_file, write_file, modify_entity) are removed; only operations that genuinely require the extension host (clipboard, shell, opening editor tabs for the user, document selection) remain at tier 4. Any code path that flips this priority must escalate via a new ADR.

### Alternatives Considered

- **Keep v1's mixed local+MCP tool registry as-is** — Rejected: Today's tool collisions (local write_file vs MCP create_file, etc.) and unclear precedence cause silent behavior changes when MCP availability flips; this is exactly the patch-stacking smell the rewrite must eliminate.
- **Pure MCP, no local fallback** — Rejected: Some operations (clipboard access, shell execution against the user's workspace) are extension-host-only capabilities that the daemon genuinely cannot provide; a pure-MCP rule would force unnatural detours.
- **Let the LLM decide priority case-by-case** — Rejected: Violates the 99.999999% tool-selection reliability target; relies on prompt discipline rather than structural enforcement, and the LLM's choice would be invisible to audit.

## Consequences

- MCP/DreamGraph is structurally privileged in every tool call; graph-first is enforced by the dispatcher, not by prompt discipline.
- Tool-selection trace is machine-readable and auditable per call — future drift is detectable.
- Tool collisions disappear because local duplicates of MCP tools are removed; only extension-host-unique operations remain at tier 4.
- Adding a new tool requires explicit tier assignment, making the priority order self-documenting.

**Risks accepted:**
- Some MCP tools may have higher latency than local equivalents; users may notice slower file operations. Mitigation: cache hot reads at the dispatcher tier, not at the tool tier.
- Tier 4 boundary judgments (when is VS Code API genuinely required?) need consistent enforcement during code review.
- Removing local duplicates means MCP availability becomes a hard dependency; daemon down = degraded experience. Mitigation: clear UX signal when MCP is unreachable.

## Guard Rails

> ⚠️ Do not call a VS Code editor API for an operation an MCP tool can perform.

> ⚠️ Do not reintroduce local duplicates of MCP file-mutation tools (write_file, edit_file, edit_entity, etc.).

> ⚠️ Do not bypass the dispatcher to call a tool directly — all calls flow through the prioritized registry.

> ⚠️ Do not skip the tier-trace log for any tool invocation.

> ⚠️ Do not flip the tier order for a single call without recording a new ADR.
