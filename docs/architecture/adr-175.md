# ADR-175: ContextBuilder is the RelevanceEngine; manifest-driven retrieval with graceful sparse-fallback

**Date:** 2026-05-09T23:15:17.089Z  
**Status:** accepted  
**Decided by:** collaborative  
**Affected entities:** extensions/vscode/src/architect-v2/context/builder.ts, extensions/vscode/src/architect-v2/context/fallback-signals.ts, extensions/vscode/src/architect-v2/orchestrator/adapters/dreamgraph/reader.ts, extensions/vscode/src/architect-v2/orchestrator/types.ts, extensions/vscode/src/architect-v2/orchestrator/ports.ts  

## Context

The composer declares what context it wants (ADR-174). The orchestrator wires graph access through ProjectGraphReader (ADR-171) and graph-absent operation as first-class (ADR-173). Something has to *fulfill* the composer's manifest \u2014 deciding which requirement gets which signal source, how much of the window each gets, and what to do when the requested kind cannot be satisfied. That something is the ContextBuilder/RelevanceEngine. If its design is unclear, every requirement kind grows a bespoke retrieval path and sparse-mode becomes an afterthought.

**Constraints:**
- context/*.ts MUST NOT import mcp_dreamgraph_*; only orchestrator/adapters/dreamgraph/** may.
- ContextBuilder is pure-shaped over ports: ProjectGraphReader, FallbackSignalProvider, ClockPort. No vscode/fs/http/MCP imports in context/.
- The builder MUST tolerate any subset of requirements (including empty manifest) and produce a renderable envelope.
- FallbackSignalProvider methods MUST be safe to call when no workspace is open (return empty arrays, never throw).
- SectionProvenance is additive on ContextSection (optional field) per ADR-151 widening rules.
- Unmet requirements MUST be recorded; silent omission is a violation.

## Decision

ContextBuilder is the single RelevanceEngine site. It interprets the ContextRequirementManifest declared by the composer (ADR-174), allocates a per-requirement token slice from the provider window (priority-weighted with budget hint scaling), and dispatches each requirement to one of two signal sources: ProjectGraphReader for graph-shaped kinds (architectural_decisions, adr_lineage, unresolved_blockers, prior_failed_attempts, graph_neighborhood) or FallbackSignalProvider for non-graph kinds (file_excerpts, recent_history, runtime_diagnostics, environment_state). When the reader reports richness 'sparse' or 'absent' for a requested graph kind, the builder transparently retries the same requirement against FallbackSignalProvider \u2014 no separate sparse-mode code path. Each emitted ContextSection carries SectionProvenance recording (a) which requirement it answered, (b) which source served it, and (c) whether it represents a fallback substitution. Unmet requirements are recorded as zero-content provenance entries so the composer/audit can see what was asked for and not delivered. The builder never throws on missing data; it always returns a valid envelope.

### Alternatives Considered

- **Treat sparse mode as a separate code path inside the builder ('if richness === absent { ... } else { ... }').** — Rejected: Branching on backend presence is exactly the coupling ADR-171 forbids; both modes must run the same plan, only with different signal sources answering.
- **Have the builder fail when a requirement cannot be satisfied at all.** — Rejected: ADR-173 mandates sparse mode is first-class; failure here would propagate as a blocker card and degrade UX in any unindexed project.
- **Let the builder call mcp_dreamgraph_* directly for graph reads to skip the adapter layer.** — Rejected: ADR-171 invariant; the builder must only see the ProjectGraphReader port.
- **Drop SectionProvenance and let the composer infer unmet requirements from missing sections.** — Rejected: Inference is fragile (some kinds legitimately produce no section); explicit provenance keeps the audit trail and enables metrics on chronic mismatches.

## Consequences

- Day-1 install with no graph indexed produces useful context via filesystem + diagnostics + environment fallback.
- Adding a new requirement kind requires (a) declare in composer, (b) dispatch case in builder — no other site changes.
- Adding a new signal source means implementing FallbackSignalProvider (or a new port) and wiring it; the builder's dispatch table grows by one row.
- Cognition recorded back to the graph (via ProjectGraphRecorder, already wired in 8A.1 finalize) feeds future passes — the loop closes itself.

**Risks accepted:**
- Provenance noise crowds the envelope. Mitigation: provenance is optional on ContextSection; assembler may set it only on actually-emitted sections and collect unmet entries in a side-channel field on the envelope.
- Token allocation algorithm becomes adhoc and untestable. Mitigation: allocation is one pure function (allocateBudget) with golden-file tests in 8A.5.
- Fallback substitution silently masks a graph backend regression. Mitigation: SectionProvenance includes a 'fallbackReason' when substitution occurs; metrics can surface fallback rates.
