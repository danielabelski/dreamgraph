# ADR-226: Architect plugin capabilities extend the existing manifest trust envelope

**Date:** 2026-05-31T15:28:45.808Z  
**Status:** accepted  
**Decided by:** collaborative  
**Affected entities:** feature_plugin_sdk, feature_plugin_runtime, packages/sdk/src/manifest.ts, packages/host/src/context.ts, packages/host/src/gates.ts, src/plugins/manager.ts, src/plugins/architect-contributions.ts  

## Context

Architect plugin tabs need registration, plan reads, plan-state writes, and sidebar summaries while preserving the shipped plugin SDK trust, manifest, capability, effect, telemetry, and lifecycle model.

**Constraints:**
- Architect extensions remain normal trusted DreamGraph plugins.
- The existing plugin.json manifest and engine.dreamgraph compatibility check remain authoritative.
- Every registration and invocation must be capability- and effect-gated, namespaced, telemetered, and removable on unload.
- Architect tab registration does not imply repository mutation authority.

## Decision

Extend the existing SDK manifest additively with architect:register_tab, architect:read_plan, architect:write_plan_state, and architect:register_sidebar_summary capabilities plus render_architect_tab, read_architect_plan_projection, write_architect_plan_state, and render_architect_sidebar_summary effects. Gate and telemetry-record every Architect registration and invocation under the existing trusted plugin host lifecycle.

### Alternatives Considered

- **Create a second privileged Architect plugin manifest or loader** — Rejected: A parallel plugin class would duplicate trust and lifecycle rules and create drift.
- **Allow Architect registration without capability or effect declarations** — Rejected: That would bypass the SDK's explicit authority model and observability contract.

## Consequences

- Architect tabs compose with existing discovery, validation, trust banners, telemetry, unload, and reload behavior.
- Static declarations can be checked before host registration is accepted.
- Existing SDK clients remain compatible because the extension is additive.

**Risks accepted:**
- Capability drift can occur if manifests, host gates, reject reasons, and docs are not changed together.
- New telemetry paths need focused regression tests.

## Guard Rails

> ⚠️ Do not bypass plugin.json, engine.dreamgraph compatibility, trusted loading, capability checks, effect checks, reject reasons, or telemetry.

> ⚠️ Do not create a privileged Architect plugin class outside the existing host runtime.

> ⚠️ Do not treat Architect tab registration as repository mutation authority.

> ⚠️ Keep SDK changes additive to the shipped plugin baseline.
