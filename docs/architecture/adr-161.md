# ADR-161: Slice 5 — Fixed 8-pill set on every card; computePills is pure derivation from Slice 3/4 types

**Date:** 2026-05-09T21:53:37.857Z  
**Status:** accepted  
**Decided by:** collaborative  
**Affected entities:** extensions/vscode/src/architect-v2/cards/pills.ts, extensions/vscode/src/architect-v2/cards/factory.ts  

## Context

v1 cards had no consistent way to surface architect-only signals (graph-binding, autonomy state, fallback reasons). Each card type rendered different metadata; the user could not tell at a glance whether the agent was graph-bound, in which mode, or running with a verification gate.

**Constraints:**
- PillSet shape is closed; every card has every pill
- computePills is pure (no Date.now, no I/O)
- Pill values come from Slice 3 (mode, autonomyState) and Slice 4 (tier, fallbackReason, verificationStatus) types only
- Renderers may hide pills but must not invent new ones

## Decision

Every card carries a fixed PillSet of exactly 8 fields: certainty, mode, provider, graphBound, autonomyState, tier, fallbackReason, verificationStatus. computePills() is a pure derivation from {Certainty, AutonomyMode, provider, TaskStatus, ExecutionPlan?, ToolOutcome?, VerificationEvidence?}. graphBound is derived deterministically: tier null → 'no'; tier 1\u20133 with no fallback → 'yes'; tier 1\u20133 with fallback → 'partial'; tier 4\u20135 → 'no'. fallbackReason is null unless plan.fallbackJustification exists. verificationStatus is null unless evidence (or success outcome's evidence) exists.

## Consequences

- Renderers know exactly which pills to draw
- Architect-only signals (graphBound, autonomy, tier) become visible on every card — the user can read what generic Copilot cannot show
- Pills are queryable when cards are persisted (Slice 7)

**Risks accepted:**
- 8 pills may visually crowd small cards — renderer (Slice 6) must collapse intelligently
- Adding a 9th pill in the future requires migration

## Guard Rails

> ⚠️ Do NOT add a new pill without a superseding ADR and a schema bump

> ⚠️ Do NOT compute pills from anything other than the documented inputs

> ⚠️ Do NOT let renderers invent pill values

> ⚠️ Do NOT allow nullable pills outside {tier, fallbackReason, verificationStatus} — those three are the only legitimately absent signals

> ⚠️ Do NOT branch on provider id inside pill derivation; provider is data, not control
