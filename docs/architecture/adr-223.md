# ADR-223: Standalone Architect shell tab uses WebSocket-backed pseudo-terminal embedding

**Date:** 2026-05-29T20:08:35.734Z  
**Status:** accepted  
**Decided by:** human  
**Affected entities:** standalone-architect, standalone_architect_terminal_surface, src/architect/routes.ts, package.json, package-lock.json, plans/shell-integration.md, ADR-222  

## Context

The Standalone Architect shell tab currently behaves like a text-rendered command surface with HTTP request input and SSE output around a spawned process. That does not provide a real interactive terminal contract: bidirectional streaming, stdin handling, PTY semantics, resize propagation, lifecycle coupling, or xterm-compatible rendering.

**Constraints:**
- ADR-222 remains in force: terminal output is local convenience output and is not repository fact, governed mutation, plan state, runtime identity, or browser/chat payload authority.
- The shell tab must be a real interactive terminal, not a text renderer or command form.
- A real shell requires bidirectional streaming, resize events, stdin/stdout/stderr flow, and lifecycle handling.
- The browser terminal UI must use xterm.js and the daemon must use node-pty.
- The transport for terminal interaction must be WebSocket, not normal HTTP request/response polling or SSE.
- The daemon-spawned pseudo-terminal must start in the active project root.
- On Windows the daemon shell is PowerShell; non-Windows may use bash or the configured interactive shell.

## Decision

Implement the Standalone Architect shell tab as xterm.js in the browser connected over WebSocket at /api/architect/v1/terminal/:id to a daemon-owned node-pty pseudo-terminal process. The daemon owns PTY creation, input writes, resize handling, output forwarding, close/error/exit lifecycle, and cleanup. HTTP may remain only for metadata/session management if needed, not for terminal stdin/stdout transport.

### Alternatives Considered

- **Keep HTTP input plus SSE output around child_process.spawn.** — Rejected: It renders text but does not provide a full interactive terminal with PTY behavior, bidirectional streaming, or resize support.
- **Use normal HTTP POST requests for stdin and EventSource for output.** — Rejected: A shell terminal needs a single bidirectional streaming channel with input, output, resize, and lifecycle events.
- **Expose provider-native shell/read/write routes as the terminal implementation authority.** — Rejected: Standalone Architect repository facts and governed mutations remain DreamGraph MCP authoritative; the shell tab is user-local convenience, not agent authority.

## Consequences

- The shell tab can behave like a real terminal with stdin, ANSI rendering, control sequences, interactive prompts, and terminal resize.
- The daemon boundary remains responsible for process lifecycle and cleanup.
- Browser UI code can delegate terminal rendering and fitting to xterm.js rather than maintaining a custom command form.
- The implementation can retire the current text-renderer workaround without weakening ADR-222 authority guard rails.

**Risks accepted:**
- node-pty introduces a native dependency that may require platform-specific install/build handling.
- WebSocket upgrade handling must coexist cleanly with the existing daemon HTTP route stack.
- Terminal sessions require explicit cleanup to avoid orphaned shells.
- The browser layout must reserve bounded vertical space so the xterm viewport fills the shell tab without causing page overflow.

## Guard Rails

> ⚠️ Do not implement terminal stdin/stdout/stderr transport over normal HTTP request/response.

> ⚠️ Do not keep the shell tab as a pre/input text renderer once the real terminal slice is implemented.

> ⚠️ Do not treat terminal output as DreamGraph MCP evidence or repository authority.

> ⚠️ Do not spawn PTY processes outside the active project root unless a later ADR explicitly changes the project-root policy.

> ⚠️ Do not omit terminal resize propagation from browser FitAddon to daemon node-pty.

> ⚠️ Do not leave PTY processes alive after WebSocket close, session close, daemon shutdown, or terminal tab teardown.
