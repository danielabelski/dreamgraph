# ADR-177: MemoryPort + ContextDiscoveryRecorder split incidental from deliberate cognition

**Date:** 2026-05-10T08:56:38.345Z  
**Status:** accepted  
**Decided by:** collaborative  
**Affected entities:** extensions/vscode/src/architect-v2/context/discovery-recorder.ts, extensions/vscode/src/architect-v2/context/builder.ts, extensions/vscode/src/architect-v2/orchestrator/adapters/dreamgraph/recorder.ts, extensions/vscode/src/architect-v2/memory/storage.ts  

## Context

8A.3 closed with the assembler reading from two sources (graph + fallback) and emitting provenance, but two pieces of cognition were still implicit: (a) Architect TaskState had no durable home so a VS Code reload erased the running task, and (b) per the user invariant 'all discovered cognition is still recorded back to graph', incidental artifacts surfaced by the assembler (file URIs read via fallback, graph nodes referenced by retrieval) had nowhere to land. The orchestrator's existing ProjectGraphRecorder writes deliberate cognition only (cards, decisions, outcomes, continuations) and is owned by finalize(), not by the assembler.

**Constraints:**
- DefaultContextBuilder MUST NOT block on discoveryRecorder — it is fire-and-forget (void safeCall(...)).
- ContextDiscoveryRecorder.recordDiscoveries MUST NOT throw; adapters wrap transport in try/catch.
- DefaultMemoryAdapter MUST cap PassLog history (default 200 entries) to keep workspaceState bounded.
- MemoryPort writes structural-clone-safe values only — plain objects, arrays, strings, numbers, booleans (vscode.Memento requirement).
- ContextDiscoveryRecorder lives in context/ and MUST NOT import from orchestrator/project-graph (no DecisionRecord/OutcomeRecord types leak into the discovery path).

## Decision

Two new ports land in 8A.4. (1) MemoryPort gets a DefaultMemoryAdapter backed by a KeyValueStore seam (vscode.Memento-shaped); InMemoryKeyValueStore covers tests; NullMemoryPort covers dry-runs. PassLog history is bounded (default 200 entries) so workspace state never grows unbounded. (2) A NEW narrow port ContextDiscoveryRecorder is owned by the assembler (context/) and called by DefaultContextBuilder when assembly produces concrete artifact references (file URIs from fallback excerpts/walk, graph node URIs from retrieved subgraphs). The builder calls recordDiscoveries fire-and-forget at the end of assembly; failures are swallowed. The DreamGraph adapter (orchestrator/adapters/dreamgraph/recorder.ts) implements BOTH ProjectGraphRecorder AND ContextDiscoveryRecorder against the McpClient seam, batching discoveries into wire_links calls with relation 'context_touched_via_fallback' or 'context_referenced'. Keeping the two recorder ports separate enforces that incidental cognition cannot accidentally synthesize decisions and deliberate cognition cannot accidentally write incidental data without the orchestrator's consent.

### Alternatives Considered

- **Have ContextBuilder call ProjectGraphRecorder directly with synthetic OutcomeRecords.** — Rejected: Conflates incidental reads with deliberate writes; the orchestrator's audit log would fill with synthetic outcomes that did not correspond to executor invocations.
- **Defer all write-back to the orchestrator's finalize() step using touched-file metadata pulled out of the envelope.** — Rejected: Loses the via=fallback distinction (so the graph cannot promote candidate edges to validated edges later) and forces the orchestrator to know envelope internals.
- **Persist memory directly to the filesystem from the orchestrator.** — Rejected: Couples architect-v2 to a specific persistence transport and makes the test harness do disk I/O. The KeyValueStore seam matches vscode.Memento exactly so the host wiring is a one-line bind.

## Consequences

- Architect tasks survive VS Code reload (TaskState + bounded PassLog history persisted via MemoryPort).
- Every assembled context envelope produces an audit trail in the graph: which task touched which artifacts via which path (graph vs fallback), enabling future candidate-edge promotion.
- The DreamGraph adapter is the single place mcp_dreamgraph_* tool names appear; reader + recorder + discovery recorder all share one McpClient transport seam.
- 8A.5 host wiring becomes mechanical: bind KeyValueStore to ExtensionContext.workspaceState, bind McpClient to the real MCP transport.

**Risks accepted:**
- Discovery recorder failures are silent. Mitigation: adapter has logErrors flag for tests; fire-and-forget is intentional so reads never block.
- Bounded PassLog history loses long-tail audit. Mitigation: durable graph still has the per-pass cards/decisions/outcomes; PassLog is only the orchestrator's local index.
- wire_links call shape may not match what the DreamGraph server expects. Mitigation: the adapter is the only place that knows MCP shapes; an integration test in 8A.5 will exercise it end-to-end.

## Guard Rails

> ⚠️ Test (8A.5 or 8B): DefaultContextBuilder constructed with NullContextDiscoveryRecorder must never throw even when assembly produces hundreds of discoveries.

> ⚠️ Test: DefaultMemoryAdapter.appendPassLog called > maxPassLogEntries times must keep array length === maxPassLogEntries (oldest dropped).

> ⚠️ Test: DreamGraphRecorderAdapter.recordDiscoveries with empty list must not call McpClient at all.

> ⚠️ Build-time check (Slice 8B): grep that fails if context/discovery-recorder.ts imports from orchestrator/project-graph or anywhere else outside prompts/requirements + own module.
