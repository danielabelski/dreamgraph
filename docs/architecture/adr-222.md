# ADR-222: Standalone Architect terminal does not carry daemon payload authority

**Date:** 2026-05-29T18:42:01.025Z  
**Status:** accepted  
**Decided by:** human  
**Affected entities:** standalone-architect, standalone_architect_terminal_surface, DreamGraph daemon web surface, codex-cli, src/architect/routes.ts, src/architect/cli-bridge.ts, ADR-221  

## Context

Standalone Architect needs a durable boundary clarifying that the terminal visible beside the browser surface is present for local user convenience and must not be treated as evidence of daemon payload transport, daemon authority, or product contract behavior.

**Constraints:**
- ADR facts are authoritative project decisions and must be treated as factual unless superseded through the ADR process.
- Standalone Architect remains daemon-authoritative for repository facts, governed mutations, runtime identity, plan state, and browser/chat contracts.
- The local terminal may exist for user convenience without carrying daemon payloads or representing the daemon-served UI contract.
- Provider-native shell/read/write routes must not be used as repository authority when DreamGraph MCP authority is available.
- This clarification must coexist with ADR-221: terminal visibility can be local and user-accessible while still not being the canonical payload or chat contract.

## Decision

Treat the Standalone Architect terminal as a local convenience surface only. It is not carrying daemon payloads, is not an authority for daemon-owned project facts or governed mutations, and must not be used to infer or replace daemon-normalized browser/chat payload contracts. ADR records on this boundary are factual unless explicitly deprecated or superseded.

### Alternatives Considered

- **Infer daemon payload behavior from terminal visibility or terminal output.** — Rejected: The terminal is present for local user convenience and does not carry daemon payloads.
- **Treat terminal access as a provider-native authority for repository reads, writes, or shell execution.** — Rejected: Standalone Architect repository facts and mutations remain governed through DreamGraph MCP and daemon authority.
- **Fold terminal convenience output into the canonical browser/chat product contract.** — Rejected: The daemon-normalized browser/chat contract remains distinct from local terminal convenience behavior.

## Consequences

- Future implementation and reviews will not cite terminal presence as evidence that daemon payloads are being transported through the terminal.
- Browser/chat payload behavior remains evaluated through daemon routes and MCP-governed contracts.
- Local terminal convenience can remain available without weakening daemon authority or ADR-221 guard rails.

**Risks accepted:**
- Developers may still confuse terminal visibility with daemon payload transport unless guard checks cite this ADR.
- Future adapter work may need explicit documentation for which surfaces show convenience diagnostics versus daemon payloads.
- The distinction depends on preserving daemon route inspection and MCP facts as the source of truth.

## Guard Rails

> ⚠️ Do not treat the local terminal as carrying daemon payloads for Standalone Architect.

> ⚠️ Do not use terminal output as authority for repository facts, governed mutations, plan state, runtime identity, or browser/chat payload contracts.

> ⚠️ Do not bypass DreamGraph MCP tools with provider-native terminal/read/write routes when acting on repository facts or mutations.

> ⚠️ Do not supersede this boundary by implication; use a new ADR or explicit deprecation if terminal payload semantics change.
