# ADR-127: Retarget API workflow weak-connection analysis to the specific API workflow node

**Date:** 2026-05-06T09:20:07.513Z  
**Status:** accepted  
**Decided by:** collaborative  
**Affected entities:** dreamgraph_src_api_routes, workflow, workflow_api_graph_context_loop  

## Context

A recurring weak-connection pattern used the generic workflow entity as the target for dreamgraph_src_api_routes, which blurred a concrete API orchestration workflow that now exists in the graph.

**Constraints:**
- Accepted graph facts should prefer the most specific validated or intentionally curated workflow node available.
- Generic abstraction targets should not hide concrete workflow structure when a specific workflow is architecturally real.
- Analytics interpretation should distinguish workflow model links from concrete API workflow links.

## Decision

Future interpretation of the API-routes-to-workflow weak-connection case should target workflow_api_graph_context_loop instead of the generic workflow entity when discussing convergence, analytics, and remediation.

### Alternatives Considered

- **Keep using the generic workflow entity as the primary target** — Rejected: It preserves the broad conceptual link but loses the concrete API workflow semantics now present in the graph.

## Consequences

- Recurring analytics around this case become more specific and easier to interpret.
- Future convergence analysis can distinguish conceptual workflow-model linkage from concrete API workflow linkage.
- DreamGraph architecture memory preserves the intended target refinement even before all tensions are re-derived.

**Risks accepted:**
- If a different API workflow later proves more appropriate, this targeting guidance may need revision.
- This records interpretation guidance; existing historical tension rows may still reference the older generic target.

## Guard Rails

> ⚠️ Do NOT treat the generic workflow entity as the preferred target for this API-routes case when a specific API workflow node exists.

> ⚠️ Do NOT claim historical tension rows were automatically rewritten; this ADR changes interpretation guidance, not past log records.
