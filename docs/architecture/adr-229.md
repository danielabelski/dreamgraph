# ADR-229: Architect UI treats vertical space as expensive without sacrificing usability or coherency

**Date:** 2026-06-01T10:10:37.560Z  
**Status:** accepted  
**Decided by:** human  
**Affected entities:** standalone_architect_browser_shell, visual_architect, ui_registry, vscode_chat_panel, ui_chat_panel, architect-chat-shell-v1, standalone_architect_living_plan, standalone_architect_terminal_tab  

## Context

Architect UI surfaces are data-dense operational workspaces that combine conversation, controls, status, traces, plans, review signals, and embedded tools. Unbounded vertical chrome, repeated labels, oversized spacing, and permanently expanded secondary detail reduce the amount of relevant working context visible at once. The project needs an explicit design principle for vertical-space economy without allowing compactness to make the interface harder to understand or use.

**Constraints:**
- Architect UI surfaces are data-dense and vertical viewport space is expensive.
- Optimizing vertical space is a high-priority UI design principle for Architect surfaces.
- Compactness must not degrade usability, readability, accessibility, discoverability, interaction clarity, or coherent grouping of information.
- Primary actions, current state, warnings, and task-relevant context must remain easy to identify.
- Secondary detail may use progressive disclosure, compact presentation, or foldouts when the collapsed state remains understandable and important information is not hidden by default.
- The principle applies across standalone browser Architect and VS Code Architect UI surfaces while allowing surface-specific implementation choices.

## Decision

Treat vertical space as an expensive resource in data-dense Architect UI surfaces. Prefer compact, information-efficient layouts, bounded chrome, concise labels, coherent grouping, and progressive disclosure for secondary detail. Evaluate new and revised Architect UI designs for vertical-space cost as a high-priority concern. Compactness is subordinate to usability and coherency: do not reduce spacing, hide information, compress controls, or collapse structure when doing so harms comprehension, accessibility, discoverability, interaction reliability, or the clear presentation of primary state and actions.

### Alternatives Considered

- **Prefer comfortable spacing and permanently expanded detail throughout Architect UI surfaces.** — Rejected: This consumes scarce viewport height and reduces visible operational context in data-dense workflows.
- **Maximize density as an overriding rule, even when labels, spacing, or hierarchy become harder to understand.** — Rejected: Vertical-space savings are not valuable when they degrade usability, coherency, accessibility, or interaction clarity.
- **Apply compactness only to individual components without a shared Architect UI principle.** — Rejected: Local optimizations alone allow repeated chrome and inconsistent density decisions to accumulate across the overall workspace.

## Consequences

- Architect UI reviews explicitly consider vertical-space cost alongside functionality.
- More task-relevant context remains visible within the viewport through compact layout, bounded chrome, and appropriate progressive disclosure.
- Architect surfaces converge on information-efficient patterns without forcing identical layouts across browser and VS Code implementations.
- UI density changes retain clear hierarchy and interaction quality because compactness is constrained by usability and coherency.

**Risks accepted:**
- Compactness may be over-applied and create visually crowded interfaces if usability constraints are ignored.
- Progressive disclosure may hide important state if primary versus secondary information is classified incorrectly.
- Surface-specific density choices may drift unless reviews apply the principle consistently.

## Guard Rails

> ⚠️ Do not introduce avoidable vertical chrome, oversized spacing, repeated labels, or permanently expanded secondary detail in Architect UI surfaces without a usability justification.

> ⚠️ Do not optimize vertical space in ways that degrade readability, accessibility, discoverability, interaction clarity, or coherent information grouping.

> ⚠️ Do not hide primary actions, current state, warnings, or task-relevant context behind progressive disclosure solely to reduce height.

> ⚠️ Do not treat maximum density as the goal; vertical-space economy is a high-priority design principle bounded by usability and coherency.

> ⚠️ Review Architect UI changes that materially increase vertical footprint or materially compress layout against this ADR.
