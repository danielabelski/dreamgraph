# ADR-133: DreamGraph plugin packages use the dreamgraph-plugin-* naming convention

**Date:** 2026-05-08T11:23:46.429Z  
**Status:** accepted  
**Decided by:** human  
**Affected entities:** plans/DREAMGRAPH_SDK_ROADMAP.md, plugin-sdk:package-naming, marketplace:plugin-discovery  

## Context

The SDK roadmap needed a stable naming convention for plugin discovery, marketplace indexing, and ecosystem expectations.

**Constraints:**
- Plugin packages need recognizable naming for discovery and review.
- The convention should be simple enough for package registries and documentation.
- A stable prefix helps separate DreamGraph plugins from unrelated packages.

## Decision

Lock in dreamgraph-plugin-* as the package naming convention for DreamGraph plugins.

### Alternatives Considered

- **Use @dreamgraph/plugin-* only** — Rejected: A scoped-only convention may not fit all registries or community package ownership patterns.
- **Allow arbitrary package names with manifest metadata only** — Rejected: Would make discovery, review, and ecosystem scanning less predictable.

## Consequences

- Plugin authors have a clear naming target.
- Discovery and marketplace tooling can prioritize the dreamgraph-plugin-* prefix.
- Documentation can present one canonical naming convention.

**Risks accepted:**
- Prefix squatting or malicious lookalike packages remain possible in public registries.
- Some high-quality integrations may use nonconforming names and need explicit allowlisting or aliases.

## Guard Rails

> ⚠️ Use dreamgraph-plugin-* as the canonical public plugin naming convention.

> ⚠️ Do not rely on naming alone as proof of trust or safety.

> ⚠️ Marketplace and installer flows must still validate manifest, signing or allowlist status, and declared capabilities.
