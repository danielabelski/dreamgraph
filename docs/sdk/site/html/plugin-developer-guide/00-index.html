DreamGraph Plugin Developer Guide

Audience: Engineers writing third-party plugins against @dreamgraph/sdk. Engine baseline: v13.0.0 "Cognitive Maintenance" (M0-M6 implemented; graph-health diagnostics, confidence-aware semantic enrichment, targeted dream stabilization, and structured Explorer knowledge inspection are current). Companion: see the Plugin Reference Manual for strict, normative tables.

This guide is task-oriented. It walks you from "what is a plugin" through a working example, then explains every seam, the trust model, lifecycle, telemetry, testing, and the practices DreamGraph expects.

Table of contents

  1. Introduction — what a plugin is and is not.
  2. Quickstart: Hello Events — five-minute end-to-end install.
  3. Anatomy of a plugin — files, packaging, ESM rules.
  4. Manifest and capabilities — plugin.json, intent, effects.
  5. The PluginContext — what ctx exposes (and what it deliberately does not).
  6. Seams: tools and resources — the MCP-facing surface.
  7. Seams: events — subscribe, emit, stable vs experimental.
  8. Seams: UI, policies, archetypes, markdown fences — the M6 closure surface.
  9. Trust and security model — in-process today, worker isolation tomorrow.
  10. Installation and lifecycle — discovery, trust, restart, hot-disable.
  11. Telemetry, debugging, testing — plugin.* events and the test harness.
  12. Best practices and pitfalls — naming, naming, naming. And quotas.
  13. Architect tabs — declarative standalone Architect tabs, explicit plan scope, persistence, and actions.
